# Играбельный срез HOSTFALL v2

Три эпизода, один причинный движок. Время идёт за действия; tick равен 30 игровым секундам. Чтение бесплатно.

## Первый сигнал — обучение

Миссия `training`, seed `NIGHT-0317`. На WS уже есть задача, первый переход к APP занимает 12 тиков. Нина выдаёт по одному шагу; переход происходит после соответствующего принятого действия.

| Шаг | Tick после действия | Результат |
|---|---:|---|
| Открыть карточку чужого входа | 0 | Узнать контекст GW → WS |
| Спросить подрядчика | 1 | Сотрудница отрицает вход |
| Отозвать доступ | 2 | Пропуск закрыт; датчик видит оставшееся соединение |
| Проверить процессы WS | 4 | Найдена самостоятельная remote-maint |
| Изолировать WS | 5 | Переход к APP прерван |
| Удалить найденную задачу | 6 | Локальная опора удалена |
| Вернуть WS в сеть | 7 | Работа восстановлена |
| Проверить результат | 10 | clean, 0 утечки, 0 простоя |

Прогресс урока и мир восстанавливаются после reload. Неподходящий выбор узла оставляет актуальную команду доступной. Учебный итог предлагает самостоятельный срочный инцидент.

## Тихий вход — расследование

Миссия `night`; canonical `NIGHT-0317` начинается с украденной сессии и локальной задачи WS. До вмешательства APP достигается на tick 8, закрепление на tick 10, пакет на tick 12, передача по 25 на ticks 13–16. Seed меняет исходную опору и длительность перехода 6–8. Backup — отдельная легитимная активность.

Точный вариант: проверить WS (2), изолировать (3), отозвать (4), удалить найденную задачу (5), подключить (6), проверить итог (9). Заказы работают, доступ устранён. Если сначала потратить время на архив, противник успеет продвинуться; найденный на APP процесс требует собственной очистки. Проверка IdP не раскрывает задачи endpoint.

## Последний рубеж — срочное реагирование

Миссия `breach`: украденная сессия уже закрыта, APP контролируется локально, пакет из 100 единиц готов, первый transfer случится на следующем тике. Начальные наблюдения — аудит пакета и открытый внешний поток. Это другой начальный мир, не новый текст к старой задаче.

| Прохождение | Последствия |
|---|---|
| Перекрыть exchange → проверить APP → удалить → итог | clean: 0 утечки, 0 простоя. За время проверки появляется наблюдение запасного почтового маршрута |
| Проверить APP → перекрыть exchange → удалить → итог | costly: 50 единиц успели уйти за два тика проверки |
| Изолировать APP → восстановить образ → подключить → итог | costly: 0 утечки, 2:30 простоя |
| Изолировать APP → проверить → восстановить образ | failure: достигнут предел 3:00 простоя до окончания восстановления |
| Только закрыть оба канала и завершить | incomplete: сдерживание оставило локальный доступ |

Почтовый обход требует реально доступных APP → MAIL → GW и открытого mail. Блокировка не возвращает уже переданные данные; очистка удаляет подготовленный пакет, сохраняя полезные сервисы.

## Проверка готовности

Автотесты проходят настоящий учебный набор команд и воспроизводят все перечисленные различия. В браузере проверяются фактические кнопки, сохранение шага, объяснения, подтверждение остановки магазина, итог, журнал и responsive-раскладка. Подробный статус Websim — в WEB_SIM_DEPLOYMENT.md. Темп 2–6 минут и интерес к повторному прохождению требуют проверки на людях.
