# Acceptance and test plan

Each iteration gate is mandatory; no status marked complete from compilation alone. Save receipts under `.artifacts/hostfall2-20261117/` and update ITERATION_STATUS after meaningful steps.

1. Pure model: VFS path/options/quote/error limits, safe shell, completion/history, guide search; Snake turns/growth/loss/retry/reachable food/fixed-step timing/exact resume; idempotent milestones, typed world actions, archive revisions and corrupted-save rejection. Round-trip Unity JSON as well as C# objects.
2. Editor/static: all 13 unique stations and required targets resolve; no duplicate Home/SOC ID; no active autoplay interactors; knowledge absent outside home; all authored puzzle witnesses validate; materials and colliders match actual objects.
3. Play: interact through actual CharacterController/raycast, correct camera/input mouse/keyboard/exit, real window drag/close/app switching and file manager; stage effects update actual vents/doors; vent telegraph/release path is clear; player can fight/EMP/evade then resume exact Snake; return home and read the delivered file via shell. Save/reload at each transition, re-open completed PC, death, early home return, alternate route, power changes.
4. Iteration2: every game wins/loses/retries with correct world effects, all computer progression reachable and returnable, recovery gates central route. Minesweeper solver proof and platformer checkpoint traversal are actual tests.
5. Iteration3: perception cannot see through walls; squads lose outdated knowledge; attack token cap, wall/floor navigation; each boss phase/weakpoint/telegraph/recovery; ventilation blocked/unblocked; face-lunge escape/intensity settings. Real arena captures and combat time budgets.
6. Iteration4: zone load/unload during save, active-computer/boss pinning, graph/physics/hole audit, profiling CPU/GPU/memory/GC and loading, native macOS plus Web build/smoke, then an automated full route from home to the final cinematic. Label visual/native/automated limits honestly.

User saves/prefs are hashed/backed up and isolated; no QA iteration may overwrite them. Old 1.x tests measure the preserved legacy contracts, not acceptance of the new route. Rework scene assertions whose intended behaviour has been explicitly replaced; never suppress genuine failures.

For the route portion of iteration2, a connected Play test starts at the actual
shelter spawn and keeps the same CharacterController for each leg. Every gate
must use its own live access rule. The clearance run isolates combat bodies so
that a blocked route identifies the geometry or progression state. Separate
combat and native playthrough checks cover robot interference.

The Recovery-specific scenario verifies all three desktop stages, a private
mid-sequence slot, the physically accessible transport, a pause and reload with
the passenger below ground, both shuttle directions and the walking approach
through the core gate. This scenario and the connected clearance run cover
different parts of the gate.
