# Каталог знаний HOSTFALL

Редакционная выгрузка содержимого Unity.

## Терминал · terminal

Терминал принимает команды и показывает ответы компьютера.

Терминал — окно для обмена текстовыми командами и ответами с компьютером. В обычной системе пользователь вводит действие и подтверждает его. В HOSTFALL сеанс ведёт сам герой: вы видите его работу и можете разбирать запись.

Первое слово команды выбирает действие, следующие уточняют его. Например, cat notes.txt читает файл: cat — действие, notes.txt — имя файла. pwd показывает текущую папку. Команды чтения показывают сведения, команды изменения вмешиваются в состояние системы.

Ответ важен не меньше запроса. Успех одной операции не означает успеха всех остальных. Записи сеанса помогают восстановить последовательность и понять, на каком шаге изменилось состояние компьютера.

Пример (text):
```
команда аргумент
```
Результат: Общая схема: параметры заменяют реальными значениями исследуемой системы.

Частая ошибка: Очистка экрана не удаляет файлы и не останавливает процессы.

## Процессы и службы · process

Процесс выполняет работу сейчас. Служба управляет тем, как эта работа запускается.

Процесс — работающий экземпляр программы. Система различает процессы по PID — числовому идентификатору. Команда ps показывает их список. По нему можно узнать, что выполняется, но одно имя программы ещё не объясняет её назначение.

Служба управляет запуском программы и может восстанавливать процесс после сбоя. Поэтому исчезновение одного PID не всегда означает прекращение работы. Представьте автоматического смотрителя маяка: если исполнитель остановился, управляющая система запускает замену.

status запрашивает состояние службы, stop останавливает текущее выполнение, disable меняет её обычный автозапуск. Это разные операции. Какую применять, зависит от желаемого результата. Имя службы и номер процесса получают из исследуемой системы.

В записи systemctl status <служба> угловые скобки обозначают место для имени. Их не вводят: вместо <служба> подставляют найденное имя.

Пример (text):
```
systemctl status <служба>
systemctl stop <служба>
systemctl disable <служба>
```
Результат: Общая схема: параметры заменяют реальными значениями исследуемой системы.

Частая ошибка: kill завершает выбранный процесс, но служба с правилом перезапуска может создать новый.

## Файлы и папки · filesystem

Файловая система помогает находить и хранить данные по пути.

Файл хранит данные, а папка помогает организовать файлы и другие папки. Чтобы прочитать нужный файл, компьютеру нужно знать его путь — расположение в этой структуре.

pwd показывает текущую папку. ls перечисляет её содержимое, cat notes.txt читает текст заметки. Команда cd /var/log переходит в папку журналов, и следующий ls уже показывает записи там.

Эта последовательность помогает сначала сориентироваться, затем читать. Имя файла само по себе не раскрывает его содержимое. На другом компьютере такая же папка может хранить совсем другие записи: обращайте внимание и на узел, и на путь.

Пример (text):
```
pwd
ls [путь]
cat <файл>
```
Результат: Общая схема: параметры заменяют реальными значениями исследуемой системы.

Частая ошибка: Относительный путь зависит от текущей папки. Если файл не найден, проверьте pwd и его имя.

## Адрес узла · ip

IP-адрес помогает определить узел в сети.

IP-адрес нужен для доставки данных по сети. Например, 192.0.2.7 — адрес IPv4: четыре числа, разделённые точками. Он относится к сетевому интерфейсу, а не доказывает личность собеседника.

Человеку удобнее запомнить имя вроде beacon.example. Сетевая система может сопоставить его с адресом. На космическом маяке имя не обязано меняться после замены оборудования, хотя адрес может стать другим.

Адрес определяет направление доставки, но не конкретную программу. Для неё нужен порт. Работоспособность соединения зависит также от маршрута, доступности узла и правил сети.

Пример (text):
```
Имя: beacon.example
Адрес: 192.0.2.7
```
Результат: Общая схема: параметры заменяют реальными значениями исследуемой системы.

Частая ошибка: Знание адреса не гарантирует связь: питание, маршрут и правила доступа тоже важны.

## Сервер · server

Сервер принимает запросы и предоставляет данные или услугу.

Сервер — программа, которая принимает запросы и предоставляет данные или услугу. Тем же словом часто называют компьютер, на котором она работает. Программа, отправляющая запрос, выступает клиентом.

Например, навигационный терминал просит карту у хранилища. Терминал здесь клиент, а программа, выдающая карту, — сервер. Если хранилище само запрашивает время у другого сервиса, оно уже играет роль клиента.

Роль зависит от обмена, а не от размера корпуса. На одной машине могут работать несколько серверных программ. Остановка одной из них не означает остановку остальных.

Пример (text):
```
Клиент → запрос карты → сервер
Клиент ← данные карты ← сервер
```
Результат: Общая схема: параметры заменяют реальными значениями исследуемой системы.

Частая ошибка: Посмотрите hostname, затем ps: сначала убедитесь, какой узел проверяете.

## HTTP · http

HTTP задаёт правила обмена запросами и ответами.

HTTP — правила обмена запросами и ответами между программами. Клиент просит ресурс или действие, а сервер сообщает результат. Например, браузер использует такие запросы при открытии страниц.

В приведённой записи GET — метод запроса, /status — путь ресурса, HTTP/1.1 — версия протокола. Строка Host указывает имя сервера. Адрес facility.example вымышленный: это образец сообщения, а не работающий сервис.

Ответ обычно содержит код состояния: 200 означает успешную обработку в рамках его смысла, 404 — что ресурс не найден. Код относится к конкретному запросу, а не ко всему компьютеру. Защиту передачи обеспечивает HTTPS с TLS; обычный HTTP её сам не добавляет.

Пример (text):
```
GET /status HTTP/1.1
Host: facility.example


```
Результат: Схема текстового запроса HTTP/1.1; ответа без сервера нет. Адрес вымышленный.

Частая ошибка: Сначала смотрите статус, затем тело ответа. Красивый текст ответа сам по себе не доказывает успех.

## Контейнер · container

Контейнер запускает процесс в изолированном окружении с заданными ограничениями.

Приложению нужны не только инструкции, но и окружение: библиотеки, файлы и настройки. Контейнер помогает запускать процесс с подготовленным окружением и ограничениями доступа к ресурсам.

Образ — основа для создания контейнера. Из одного образа можно создать несколько экземпляров с разными настройками и состояниями. Контейнеры используют ядро хостовой системы; это не отдельная полноценная ОС для каждого экземпляра.

docker ps в настоящей настроенной среде показывает работающие контейнеры. В терминале станции эта команда не реализована. Здесь она помогает узнать инструмент и понять разницу между образом и экземпляром.

Пример (shell):
```
docker ps
```
Результат: При настроенном Docker показывает работающие контейнеры; в игре команда пока не реализована.

Частая ошибка: Остановка контейнера и удаление данных — разные действия. Важные данные нужно хранить отдельно от временного экземпляра.

## Kubernetes · kubernetes

Kubernetes помогает управлять группой контейнеризированных приложений.

Когда контейнеров много, нужно следить, где они запускаются и что делать при сбое. Kubernetes помогает управлять такими приложениями на группе машин.

Вы задаёте желаемое состояние, например два экземпляра приложения. Контроллер наблюдает текущее состояние и пытается восстановить недостающее. Поэтому удаление одного Pod, единицы запуска контейнеров, может привести к появлению замены.

В настоящем настроенном кластере kubectl get pods показывает Pod, get deployments — управляющие развёртывания, get services — объекты доступа к приложениям. Игровой терминал эти команды не выполняет. Остановка исполнителя и изменение управляющего правила — разные действия.

Пример (shell):
```
kubectl get pods
kubectl get deployments
kubectl get services
```
Результат: Списки объектов активного контекста при настроенном кластере. В игровом терминале эти команды пока не поддерживаются.

Частая ошибка: Проверяйте, кто управляет объектом. Удаление экземпляра не всегда меняет желаемое состояние.

## Python: первая программа · python.start

Программа — это последовательность инструкций для компьютера.

Компьютер выполняет записанные инструкции. Например, можно попросить его показать название станции, а затем число. В Python для вывода используют print: в скобках указывают, что показать.

Текст записывают в кавычках, чтобы отличить его от имён в программе. Число 4 можно написать без кавычек. В примере ниже первая строка выводит NORTHLINE, вторая — 4. По умолчанию print завершает вывод переводом строки.

Знак # начинает комментарий: заметку для человека, которую Python не выполняет. Комментарий помогает объяснить замысел, но сам по себе не меняет работу программы.

Пример (python):
```
print("NORTHLINE")
print(4)
```
Результат: NORTHLINE
4

Частая ошибка: Кавычки должны быть обычными: " или '. Типографские «ёлочки» не заменяют их.

## Переменные и присваивание · python.variables

Переменная даёт имя значению, с которым работает программа.

Допустим, нужно запомнить оставшийся заряд. Запись charge = 4 связывает имя charge с числом 4. Когда программа встречает это имя, она получает связанное с ним значение.

В строке charge = charge - 1 сначала вычисляется выражение справа: 4 - 1 даёт 3. Затем charge связывается с новым значением. Последняя строка print(charge) показывает 3.

Знак = здесь означает присваивание. Он позволяет обновить данные: например, уменьшить заряд после использования прибора. Имя charge выбрано человеком; понятное имя помогает читать код.

Пример (python):
```
charge = 4
charge = charge - 1
print(charge)
```
Результат: 3

Частая ошибка: Имена чувствительны к регистру: charge и Charge — разные имена.

## Числа, строки и логические значения · python.types

Тип определяет допустимые операции над значением.

С числом можно считать, а текст можно показывать или разбирать. Тип значения помогает Python определить, какие действия допустимы. int обозначает целые числа, float — числа с дробной частью, str — строки текста, bool — два логических значения: True и False.

В примере "7" сначала является текстом. int("7") разбирает эту строку и получает число 7. Поэтому port + 1 даёт 8. Проверка isinstance(port, int) спрашивает, относится ли port к целым числам, и возвращает True — «да».

Если написать "7" + 1, получится ошибка: текст и число нельзя так складывать. Явное преобразование показывает, что вы хотите сделать с данными.

Пример (python):
```
port = int("7")
print(port + 1)
print(isinstance(port, int))
```
Результат: 8
True

Частая ошибка: Аннотация x: int сама по себе не проверяет входные данные во время выполнения.

## Вычисления и сравнения · python.operators

Выражения вычисляют новые значения, не меняя исходные сами по себе.

Операторы — знаки и слова, которые задают действие над значениями. Например, + складывает числа, а < сравнивает их. Результат сравнения — True или False: условие выполняется или нет.

В первой строке примера 7 // 3 даёт 2, а 7 % 3 даёт 1. Это целая часть деления и остаток: из семи предметов получаются две группы по три и один предмет остаётся. Обычное деление 7 / 2 даёт 3.5.

Последняя строка проверяет сразу два сравнения. 3 < 5 и 5 < 8 верны, поэтому выражение с and тоже даёт True. Для and нужны оба условия; для or достаточно одного. Скобки помогают явно показать нужный порядок вычислений.

Пример (python):
```
print(7 // 3, 7 % 3)
print(7 / 2)
print(3 < 5 and 5 < 8)
```
Результат: 2 1
3.5
True

Частая ошибка: = присваивает, == сравнивает. Не подменяйте одно другим.

## Условия: if, elif, else · python.conditions

Условие выбирает ветку действий по текущим данным.

Программе часто нужно выбрать действие по текущим данным. Например, прибор с нулевым зарядом выключен, с небольшим зарядом требует внимания, а с достаточным готов к работе.

В примере charge равно 2. Первая проверка сравнивает его с нулём и не подходит. Следующая проверка спрашивает, меньше ли заряд трёх. Она подходит, поэтому выводится low — «низкий заряд». Остальные варианты в этой цепочке уже не выполняются.

if начинает проверку, elif добавляет следующий вариант, else выполняется, если предыдущие проверки не подошли. Двоеточие и отступы показывают, какие строки относятся к выбранному варианту.

Пример (python):
```
charge = 2
if charge == 0:
    print("offline")
elif charge < 3:
    print("low")
else:
    print("ready")
```
Результат: low

Частая ошибка: else не получает собственного условия. Для ещё одной проверки нужен elif.

## Цикл for и range · python.for

Цикл повторяет один и тот же набор действий для нескольких значений.

Представьте три датчика: их показания нужно сложить. Вместо трёх похожих команд можно написать цикл. В Python for по очереди берёт значения и выполняет для каждого строки с отступом. Один такой проход называют итерацией.

В примере range(1, 4) даёт числа 1, 2 и 3. Число 4 служит границей и в перебор не входит. На каждом проходе очередное число добавляется к total: сначала получается 1, затем 3, затем 6.

Начальное значение total задают до цикла. Если каждый раз обнулять сумму внутри, предыдущие результаты потеряются. Команда вывода после цикла показывает итог один раз.

Пример (python):
```
total = 0
for reading in range(1, 4):
    total += reading
print(total)
```
Результат: 6

Частая ошибка: range(4) начинает с нуля. Четыре повторения не означают числа от 1 до 4.

## Цикл while и условие остановки · python.while

Цикл while повторяет действие, пока выполняется условие.

Иногда число повторений зависит от происходящего. Например, проверку можно повторять, пока остались попытки. Перед каждым проходом while проверяет условие: attempts > 0 означает «попыток больше нуля».

В примере attempts сначала равно 3. Программа выводит это число и уменьшает его на единицу. Затем так же обрабатывает 2 и 1. Когда значение становится 0, условие перестаёт выполняться и цикл заканчивается.

Если убрать уменьшение attempts, условие останется истинным и повторение не закончится. Поэтому при чтении while полезно сразу найти, что меняется и при каком значении работа остановится.

Пример (python):
```
attempts = 3
while attempts > 0:
    print(attempts)
    attempts -= 1
```
Результат: 3
2
1

Частая ошибка: Не меняйте условие остановки лишь в ветке, которая может никогда не выполниться.

## break и continue · python.loop-control

break завершает цикл, continue пропускает остаток текущего шага.

При обходе данных иногда нужно пропустить одну запись или закончить весь обход. continue пропускает оставшиеся действия текущего прохода, а break немедленно завершает ближайший цикл.

В примере последовательно встречаются 2, -1, 3, 0 и 9. Число 2 выводится. Для -1 срабатывает continue: программа возвращается к началу цикла и берёт следующий элемент. Число 3 тоже выводится. При 0 срабатывает break, поэтому до 9 выполнение уже не доходит.

Получаются две строки: 2 и 3. Ноль здесь выбран автором программы как признак окончания данных. Python не придаёт ему такой смысл сам по себе.

Пример (python):
```
for value in [2, -1, 3, 0, 9]:
    if value < 0:
        continue
    if value == 0:
        break
    print(value)
```
Результат: 2
3

Частая ошибка: continue в while может пропустить обновление счётчика и создать бесконечный цикл.

## Функции и возвращаемое значение · python.functions

Функция даёт имя небольшому действию и принимает входные данные.

Если один расчёт нужен в нескольких местах, ему можно дать имя и оформить как функцию. При вызове функции передают данные, а она возвращает результат. Так проще менять расчёт в одном месте.

def remaining(charge, spent) объявляет функцию с двумя параметрами — именами входных значений. Вызов remaining(8, 3) передаёт 8 в charge и 3 в spent. Строка return charge - spent вычисляет 5 и возвращает это число вызывающему коду.

Затем print показывает полученное число. return и print решают разные задачи: return отдаёт результат для дальнейшей работы, print выводит его на экран. Функция не обязана что-либо печатать.

Пример (python):
```
def remaining(charge, spent):
    return charge - spent

print(remaining(8, 3))
```
Результат: 5

Частая ошибка: Функция без return с выражением возвращает None, а не последнюю вычисленную строку.

## Область видимости · python.scope

Локальные имена функции не подменяют одноимённые внешние значения.

Одинаковое имя в разных частях программы не всегда обозначает одно и то же значение. Область видимости — участок, где доступно имя. Параметры функции относятся к её собственному вызову.

Снаружи charge равно 8. Вызов reduce(charge) передаёт это значение внутрь функции. Её параметр тоже называется charge, но вычисление charge - 3 не меняет внешнюю переменную. Функция возвращает 5.

Поэтому print выводит 5 8: результат функции и прежний внешний заряд. Чтобы сохранить результат снаружи, нужно явно присвоить его, например charge = reduce(charge). Такая передача данных делает изменения заметными при чтении кода.

Пример (python):
```
charge = 8
def reduce(charge):
    return charge - 3

print(reduce(charge), charge)
```
Результат: 5 8

Частая ошибка: Не добавляйте global лишь для обхода ошибки области видимости: сначала уточните вход и результат функции.

## Строки и обработка текста · python.strings

Строка — неизменяемый текст; методы возвращают новый результат.

Строка хранит текст. Перед обработкой текст часто приходится привести к ожидаемому виду: убрать случайные пробелы, договориться о регистре букв и отделить поля.

В примере record содержит пробелы по краям и запись BEACON:READY. strip убирает крайние пробельные символы, lower переводит буквы в нижний регистр, split(":") разделяет текст по двоеточию. Две полученные части записываются в name и state.

Вывод beacon ready показывает разобранное имя и состояние. Методы создают новые строки; исходная record сама по себе не изменяется. Для внешнего ввода дополнительно нужна проверка, что разделитель есть и частей действительно две.

Пример (python):
```
record = "  BEACON:READY  "
name, state = record.strip().lower().split(":")
print(name, state)
```
Результат: beacon ready

Частая ошибка: Не рассчитывайте, что split всегда даст ровно два элемента: для внешних данных нужна проверка формата.

## Списки и индексы · python.lists

Список хранит изменяемую последовательность значений.

Список хранит несколько значений в определённом порядке. Например, можно собрать в него показания датчиков, а затем обращаться к отдельным показаниям или перебирать все.

В начале readings содержит 4 и 7. Вызов append(9) добавляет 9 в конец. Теперь список состоит из трёх элементов. readings[0] берёт первый элемент, а readings[-1] — последний. len(readings) сообщает количество элементов.

Результат 4 9 3 означает: первое показание 4, последнее 9, всего три показания. Положительные индексы начинаются с нуля, поэтому у списка длиной 3 допустимы индексы 0, 1 и 2. Индекс 3 уже за границей.

Пример (python):
```
readings = [4, 7]
readings.append(9)
print(readings[0], readings[-1], len(readings))
```
Результат: 4 9 3

Частая ошибка: Присваивание b = readings не копирует список: оба имени указывают на один объект.

## Словари: доступ по ключу · python.dict

Словарь связывает уникальный ключ с данными.

Словарь позволяет находить данные по ключу. Это удобно, когда важнее имя объекта, чем его место в последовательности: например, состояние поста можно искать по его имени.

В примере ключ "beacon" связан со строкой "ready" — «готов». Следующая строка добавляет запись "kiln": "busy" — «занят». Обращение states["beacon"] возвращает ready.

Для scanner записи нет. Вызов get с запасным значением "unknown" возвращает unknown — «неизвестно», вместо ошибки отсутствующего ключа. Это означает только отсутствие записи. По нему нельзя заключить, что пост выключен или неисправен.

Пример (python):
```
states = {"beacon": "ready"}
states["kiln"] = "busy"
print(states["beacon"])
print(states.get("scanner", "unknown"))
```
Результат: ready
unknown

Частая ошибка: Обращение states["missing"] выбрасывает KeyError; не скрывайте неожиданные пропуски общим except.

## Множества и уникальные значения · python.sets

Множество удобно для проверки принадлежности и удаления повторов.

Множество хранит уникальные значения. Оно подходит, когда нужно узнать, встречался ли объект, а порядок и число повторов не важны.

В примере beacon указан дважды, но в seen остаётся один такой элемент. Вместе с kiln получается два уникальных имени, поэтому len(seen) выводит 2. Проверка "scanner" in seen даёт False: этого имени нет.

Порядок элементов множества не следует использовать как порядок обхода постов. sorted(seen) создаёт отсортированный список для удобного, предсказуемого вывода: сначала beacon, затем kiln. Само множество от этой операции не меняется.

Пример (python):
```
seen = {"beacon", "beacon", "kiln"}
print(len(seen))
print("scanner" in seen)
print(sorted(seen))
```
Результат: 2
False
['beacon', 'kiln']

Частая ошибка: {} создаёт пустой словарь. Для пустого множества нужен set().

## Перебор с номером элемента · python.iteration

enumerate даёт одновременно индекс и значение.

При переборе списка бывает полезно получить одновременно элемент и его номер. enumerate добавляет счётчик к обычному обходу, поэтому отдельную переменную с ручным увеличением писать не нужно.

В примере перебираются два имени: beacon и kiln. На каждом проходе number получает номер, а name — имя. Параметр start=1 задаёт начальное значение счётчика. Поэтому выводятся пары 1 beacon и 2 kiln.

Нумерация с единицы удобна для отчёта человеку. При этом позиции в исходном списке всё ещё начинаются с нуля: start меняет только счётчик enumerate, а не список и не выбор элементов.

Пример (python):
```
for number, name in enumerate(["beacon", "kiln"], start=1):
    print(number, name)
```
Результат: 1 beacon
2 kiln

Частая ошибка: Не удаляйте элементы списка, по которому сейчас идёт перебор: часть значений может быть пропущена.

## Исключения и понятные ошибки · python.errors

try/except отделяет ожидаемый сбой от успешного пути.

Программа может получить данные, с которыми не умеет работать. Например, int превращает запись числа в целое число, но слово offline числом не является. Python сообщает об этом исключением ValueError. Исключение прерывает обычный ход выполнения.

В примере попытка преобразования находится внутри try. Когда возникает ValueError, управление переходит к соответствующему except. Он выводит expected an integer — «ожидалось целое число». Программа сообщает о проблеме вместо того, чтобы продолжать расчёт с неверным значением.

Обрабатывайте конкретную ошибку, для которой известен дальнейший шаг. Если скрыть любые ошибки одним общим обработчиком, можно потерять признаки настоящей поломки.

Пример (python):
```
try:
    port = int("offline")
except ValueError:
    print("expected an integer")
```
Результат: expected an integer

Частая ошибка: except: перехватывает слишком много, в том числе сигналы завершения. Не используйте его как универсальное исправление.

## Проверка входных данных · python.validation

Успешно разобрать число ещё не значит принять допустимое значение.

Проверка ввода отвечает на два вопроса: можно ли разобрать запись и подходит ли полученное значение для задачи. Например, 70000 — целое число, но не допустимый номер TCP-порта.

Функция valid_port сначала вызывает int. Если строка не является записью целого числа, except возвращает False. Если разбор удался, сравнение проверяет диапазон от 1 до 65535 включительно.

Для "22" результат True, а для "70000" — False. Поэтому выводится True False. Функция рассчитана на строки, а не произвольные объекты. Выбор диапазона зависит от задачи: здесь нужен конкретный порт службы, поэтому нулевой номер исключён.

Пример (python):
```
def valid_port(text):
    try:
        port = int(text)
    except ValueError:
        return False
    return 1 <= port <= 65535

print(valid_port("22"), valid_port("70000"))
```
Результат: True False

Частая ошибка: Не подменяйте проверку диапазона обрезанием значения: ошибка отправителя останется скрытой.

## Потоки и with · python.files

Контекстный менеджер завершает работу с ресурсом при выходе из блока.

При чтении данных важно не только получить текст, но и закрыть использованный ресурс. Конструкция with задаёт участок работы, после которого выполняется завершение. Для открытого файла это означает закрытие, в том числе при выходе из блока из-за ошибки.

В примере используется StringIO — текстовый поток в памяти, похожий на файл. Он содержит две строки: beacon и kiln. read читает текст, а splitlines разделяет его на строки и собирает список names.

После блока поток закрыт. Поэтому результат 2 True означает: в списке два имени, а свойство closed подтверждает закрытие потока. Сам список остаётся доступен: закрытие потока не удаляет уже прочитанные данные.

Пример (python):
```
from io import StringIO

with StringIO("beacon\nkiln\n") as stream:
    names = stream.read().splitlines()
print(len(names), stream.closed)
```
Результат: 2 True

Частая ошибка: read() без ограничения читает весь поток. Для больших файлов используйте построчный перебор или предел размера.

## Структурированные записи и JSON · python.records

Данные лучше передавать по именованным полям с явной проверкой.

Когда у записи несколько полей, полезно передавать их вместе с именами. JSON — текстовый формат таких данных: он умеет описывать числа, строки, списки и объекты с именованными полями.

json.loads разбирает текст JSON и создаёт значения Python. В примере record становится словарём. Поле host содержит beacon, а поле charge — число 3. Проверка record["charge"] > 0 даёт True, поэтому выводится beacon True.

Успешный разбор подтверждает формат, но не достоверность данных. Если запись пришла извне, проверьте наличие полей, их типы и допустимые значения перед использованием.

Пример (python):
```
import json

record = json.loads('{"host":"beacon","charge":3}')
print(record["host"], record["charge"] > 0)
```
Результат: beacon True

Частая ошибка: Не используйте eval для чтения записи данных: он исполняет выражение.

## Модули и импорт · python.modules

Модуль собирает связанные функции в отдельное пространство имён.

Модуль собирает связанный код под общим именем. Вместо того чтобы писать каждую полезную функцию самостоятельно, можно подключить готовый модуль и использовать его возможности.

В примере import math подключает стандартный математический модуль. Запись math.isqrt показывает, какую функцию и из какого модуля мы вызываем. isqrt(81) возвращает целую часть квадратного корня из 81 — число 9.

Пример (python):
```
import math

```
Результат: 9

## Проверки и граничные случаи · python.testing

Хороший тест ловит изменение поведения, а не повторяет код функции.

Тест — проверка, что программа ведёт себя так, как задумано. Полезно проверять не только очевидный случай, но и границу, где легко ошибиться в условии.

Функция enough отвечает, хватает ли заряда на расход. Для charge=3 и cost=3 заряда хватает в точности. Поэтому enough(3, 3) должна вернуть True. Для 2 и 3 ожидается False.

assert останавливает выполнение, если проверяемое условие ложно. Обе проверки проходят, и программа печатает checks passed — «проверки пройдены». Замена >= на > сломает первый тест. assert подходит для внутренних проверок при разработке; для внешнего ввода нужны обычные условия, потому что оптимизированный запуск может отключить assert.

Пример (python):
```
def enough(charge, cost):
    return charge >= cost

assert enough(3, 3)
assert not enough(2, 3)
print("checks passed")
```
Результат: checks passed

Частая ошибка: Один успешный пример не проверяет пустые данные, неверный тип и край диапазона.

## Фильтрация, сортировка и цена прохода · python.algorithms

Сначала опишите нужный результат, затем выбирайте преобразование.

Алгоритм — порядок действий, который приводит к нужному результату. Перед выбором операций полезно точно сформулировать задачу: какие данные оставить и в каком виде получить ответ.

В примере из показаний 7, -1, 3, 7 выбираются только положительные. Выражение с for передаёт их в sorted, которая возвращает новый отсортированный список. Получается [3, 7, 7]. Отрицательное значение убрано, повтор семёрки сохранён.

Каждый просмотр данных требует времени. Фильтрация проходит по всем элементам, а сортировка делает дополнительную работу. Если нужен только максимум, можно найти его одним проходом, не сортируя весь список.

Пример (python):
```
readings = [7, -1, 3, 7]
valid = sorted(value for value in readings if value > 0)
print(valid)
```
Результат: [3, 7, 7]

Частая ошибка: Не сортируйте исходный список через sort(), если другим частям программы нужен прежний порядок.

## Ссылки на объекты и копирование · python.references

Два имени могут обозначать один изменяемый объект.

Несколько имён могут указывать на один список. Присваивание b = a не создаёт второй список: оба имени дают доступ к тем же данным.

В примере через b добавляется число 2. Оно появляется и при обращении через a, потому что список общий. Затем a.copy() создаёт отдельный внешний список c. Добавление 3 в c уже не меняет a.

Поэтому выводятся [1, 2] и [1, 2, 3]. Такая копия называется поверхностной: если внутри были другие списки, они могли бы остаться общими. Для простого списка чисел в примере этого достаточно.

Пример (python):
```
a = [1]
b = a
b.append(2)
c = a.copy()
c.append(3)
print(a, c)
```
Результат: [1, 2] [1, 2, 3]

Частая ошибка: is проверяет тождество объектов, == сравнивает значения. Для текста обычно нужен ==.

## Потоки и защита общего состояния · python.concurrency

Несколько потоков требуют явных правил доступа к общим данным.

Поток — отдельная последовательность выполнения внутри программы. Несколько потоков могут обращаться к общим данным, поэтому нужно договориться, как они их меняют.

В примере два потока запускают worker. Каждый двадцать раз увеличивает общий total. Lock работает как замок: пока один поток выполняет защищённый блок with lock, другой ждёт освобождения того же замка. Обе операции увеличения используют одну защиту.

start запускает потоки, а join ожидает их завершения. После двух наборов по двадцать увеличений выводится 40. Замок помогает согласовать доступ, но сам по себе не делает программу быстрее. В этом небольшом примере global явно указывает, что worker меняет внешнюю переменную total.

Пример (python):
```
from threading import Thread, Lock

total = 0
lock = Lock()
def worker():
    global total
    for _ in range(20):
        with lock:
            total += 1

a, b = Thread(target=worker), Thread(target=worker)
a.start()
b.start()
a.join()
b.join()
print(total)
```
Результат: 40

Частая ошибка: Не удерживайте замок во время долгого сетевого ожидания без необходимости.

## C++: первая программа · cpp.start

Программа C++ начинает работу с функции main.

Исходный код — текст с инструкциями для компьютера. Перед запуском программу C++ собирают компилятором: он проверяет код и переводит его в исполняемую форму. Если в записи есть ошибка, сборка может остановиться с сообщением.

В примере main обозначает место начала работы. Фигурные скобки выделяют инструкции, которые нужно выполнить. std::cout выводит данные, а знак << передаёт ему очередное значение. Запись \n в строке обозначает перевод строки.

Строка #include <iostream> подключает объявления, необходимые для такого вывода. Пока достаточно узнавать этот небольшой каркас: он позволяет собрать и запустить пример с выводом на экран.

```
#include <iostream>
```

Результат: NORTHLINE
4

## Переменные и начальное значение · cpp.variables

Переменная — именованный объект, в котором программа хранит значение.

Допустим, программе нужно хранить оставшийся заряд. В записи int charge{4} слово int задаёт целочисленный тип, charge — имя, а 4 — начальное значение. После создания переменной её имя можно использовать в вычислениях.

В строке charge = charge - 1 сначала вычисляется правая часть. Если заряд равен 4, результат будет 3. Затем это число записывается в charge. Последующий вывод показывает обновлённое значение.

Давайте переменным имена по смыслу. charge легче понять, чем случайную букву. Начальное значение тоже важно: программа должна знать, с какими данными она начинает работу.

Пример (cpp):
```
#include <iostream>

int main() {
    int charge{4};
    charge = charge - 1;
    std::cout << charge << "\n";
}

```
Результат: 3

Частая ошибка: Локальная int charge; без инициализации не задаёт пригодное значение для чтения.

## Типы: int, double, bool · cpp.types

Тип ограничивает допустимые операции и представление значения.

Тип описывает, какие значения хранит переменная и какие операции с ними допустимы. int используют для целых чисел, double — для чисел с дробной частью, bool — для логического ответа true или false.

В примере charge содержит 7. Деление на 2.0 выполняется с дробным результатом, поэтому half получает 3.5. Проверка charge > 0 даёт true — «заряд больше нуля». std::boolalpha просит выводить логические значения словами вместо цифр.

Поэтому результат — 3.5 true. Размеры и пределы числовых типов зависят от типа и платформы. Для начала важно различать целые числа, дробные числа и логические ответы, а перед расчётом проверять допустимый диапазон.

Пример (cpp):
```
#include <iostream>

int main() {
    int charge{7};
    double half = charge / 2.0;
    bool ready = charge > 0;
    std::cout << half << " " << std::boolalpha << ready << "\n";
}

```
Результат: 3.5 true

Частая ошибка: Нельзя рассчитывать, что знаковое переполнение int даст предсказуемый результат.

## Операторы и сравнения · cpp.operators

Выражение производит значение; скобки показывают порядок вычисления.

Операторы задают действие над значениями: вычисление, сравнение или сочетание условий. Например, != означает «не равно», а && требует выполнения обоих условий.

В примере divisor равно нулю. Первая часть divisor != 0 ложна, поэтому правая часть после && вообще не вычисляется. Это называется коротким замыканием. Благодаря ему программа не пытается делить 10 на ноль, а safe получает false.

Отдельно выводятся 7 / 3 и 7 % 3: целое частное 2 и остаток 1. При делении двух целых дробная часть отбрасывается с усечением к нулю. Если нужен дробный результат, хотя бы один операнд должен иметь соответствующий тип.

Пример (cpp):
```
#include <iostream>

int main() {
    int divisor{0};
    bool safe = divisor != 0 && 10 / divisor > 1;
    std::cout << 7 / 3 << " " << 7 % 3 << "\n";
    std::cout << std::boolalpha << safe << "\n";
}

```
Результат: 2 1
false

Частая ошибка: Побитовые & и | не заменяют логические && и ||.

## Условия: if и else · cpp.conditions

Условие выбирает действие по значению bool.

Программе часто нужно выбрать действие по текущим данным. Например, прибор с нулевым зарядом выключен, с небольшим зарядом требует внимания, а с достаточным готов к работе.

В примере charge равно 2. Первая проверка сравнивает его с нулём и не подходит. Следующая проверка спрашивает, меньше ли заряд трёх. Она подходит, поэтому выводится low — «низкий заряд». Остальные варианты в этой цепочке уже не выполняются.

if начинает проверку, else if добавляет следующий вариант, else выполняется, если предыдущие проверки не подошли. Условие записывают в круглых скобках, а инструкции выбранного варианта — в фигурных.

Пример (cpp):
```
#include <iostream>

int main() {
    int charge{2};
    if (charge == 0) {
        std::cout << "offline\n";
    } else if (charge < 3) {
        std::cout << "low\n";
    } else {
        std::cout << "ready\n";
    }
}

```
Результат: low

Частая ошибка: Лишняя точка с запятой после if завершает его пустой инструкцией; следующий блок уже не управляется условием.

## Цикл for: начало, условие, шаг · cpp.for

for задаёт управляемый повтор с понятной границей.

Цикл позволяет повторить действие без копирования одинаковых строк. В for со счётчиком рядом записаны начало, условие продолжения и изменение счётчика.

В примере int i{1} задаёт начало с единицы. Перед каждым проходом проверяется i < 4. После прохода ++i увеличивает i на единицу. Поэтому тело цикла получает значения 1, 2 и 3.

Запись total += i прибавляет очередное значение к сумме: 0 превращается в 1, затем в 3 и в 6. После цикла выводится 6. Начальную сумму создают перед циклом, чтобы она сохранялась между проходами, а не начиналась заново.

Пример (cpp):
```
#include <iostream>

int main() {
    int total{0};
    for (int i{1}; i < 4; ++i) {
        total += i;
    }
    std::cout << total << "\n";
}

```
Результат: 6

Частая ошибка: i <= size() выходит на индекс за концом контейнера: допустимый индекс строго меньше размера.

## Цикл while и завершение · cpp.while

while полезен, когда повтор зависит от изменяющегося состояния.

while повторяет блок, пока условие истинно. Такой цикл удобен, когда продолжение зависит от текущих данных: например, пока остались попытки проверки.

В примере attempts начинается с 3. Программа проверяет attempts > 0, выводит значение и уменьшает его через --attempts. Последовательно выводятся 3, 2 и 1. При нуле условие становится ложным, и выполнение переходит за цикл.

Условие проверяется до тела. Если attempts изначально равно нулю, тело не выполнится ни разу. Если убрать уменьшение счётчика, приведённый цикл не завершится: программа должна сама менять данные, от которых зависит остановка.

Пример (cpp):
```
#include <iostream>

int main() {
    int attempts{3};
    while (attempts > 0) {
        std::cout << attempts << "\n";
        --attempts;
    }
}

```
Результат: 3
2
1

Частая ошибка: Не превращайте ожидание в пустой бесконечный цикл, постоянно загружающий процессор.

## break и continue · cpp.loop-control

Можно пропустить отдельный шаг или завершить ближайший цикл.

continue пропускает остаток текущего прохода цикла, а break завершает весь ближайший цикл. Эти инструкции помогают обрабатывать записи с разными значениями без лишних вложенных условий.

Пример перебирает 2, -1, 3, 0 и 9. Для отрицательного -1 срабатывает continue, поэтому вывода для него нет. Ноль выбран как признак конца данных: при нём срабатывает break. До числа 9 выполнение не доходит.

На экране остаются 2 и 3. Смысл отрицательного значения и нуля задан этой программой. В другом наборе данных такие числа могут быть допустимыми показаниями, поэтому правила пропуска всегда зависят от задачи.

Пример (cpp):
```
#include <iostream>

int main() {
    for (int value : {2, -1, 3, 0, 9}) {
        if (value < 0) { continue; }
        if (value == 0) { break; }
        std::cout << value << "\n";
    }
}

```
Результат: 2
3

Частая ошибка: continue в while может пропустить уменьшение счётчика и помешать завершению.

## Функции: параметры и return · cpp.functions

Функция формулирует небольшой контракт: входы и результат.

Функция объединяет инструкции для одной задачи и даёт им имя. Входные значения передаются через параметры, а результат можно вернуть вызывающему коду.

В примере remaining принимает два целых числа: charge и spent. Слово int перед именем функции указывает, что она возвращает целое число. return вычисляет разность и завершает вызов.

При remaining(8, 3) получается 5. std::cout затем показывает это значение. Сам расчёт ничего не выводит, поэтому его можно использовать и в другой части программы. Деление на небольшие функции помогает понимать, где выполняется расчёт, а где показывается ответ.

Пример (cpp):
```
#include <iostream>

int remaining(int charge, int spent) {
    return charge - spent;
}

int main() {
    std::cout << remaining(8, 3) << "\n";
}

```
Результат: 5

Частая ошибка: У функции с результатом должен быть корректный return на каждом достижимом обычном пути.

## Область видимости и const · cpp.scope

Блок ограничивает имена; const запрещает изменение через это объявление.

Область видимости определяет, где можно использовать имя. Фигурные скобки создают блок: переменная, объявленная внутри него, обычно недоступна снаружи.

В примере charge равно 8, cost равно 3. Во внутреннем блоке создаётся remaining со значением 5 и сразу выводится. После закрывающей скобки имя remaining уже нельзя использовать. Переменная charge объявлена во внешнем блоке и остаётся доступной, поэтому затем выводится 8.

Слово const запрещает менять значение объекта после его инициализации. Так читателю видно, какие данные должны оставаться постоянными. Оно не отменяет правил области видимости.

Пример (cpp):
```
#include <iostream>

int main() {
    const int charge{8};
    int cost{3};
    {
        const int remaining = charge - cost;
        std::cout << remaining << "\n";
    }
    std::cout << charge << "\n";
}

```
Результат: 5
8

Частая ошибка: const у указателя и const у объекта, на который он указывает, описывают разные ограничения.

## std::string и текст · cpp.strings

std::string владеет последовательностью символов и её размером.

std::string хранит последовательность символов и предоставляет операции для работы с текстом. Строки удобно использовать для имён, сообщений и записей, которые нужно разобрать.

В примере name начинается со значения "MK". Операция += дописывает "12" в конец той же строки. Получается "MK12". Метод size сообщает число элементов char в строке, здесь их четыре.

Поэтому выводится MK12 4. Для простого латинского текста это совпадает с числом видимых знаков. Для текста UTF-8 один знак может занимать несколько байтов, поэтому size нельзя во всех случаях читать как число букв на экране.

Пример (cpp):
```
#include <iostream>
#include <string>

int main() {
    std::string name{"MK"};
    name += "12";
    std::cout << name << " " << name.size() << "\n";
}

```
Результат: MK12 4

Частая ошибка: Указатель, полученный из c_str(), может стать недействительным после изменения строки.

## std::vector и границы · cpp.vector

vector хранит изменяемую последовательность элементов.

std::vector хранит последовательность элементов одного типа и умеет увеличиваться при добавлении данных. Он подходит, например, для списка показаний неизвестной заранее длины.

Сначала readings содержит 4 и 7. push_back(9) добавляет третье число. at(0) берёт первый элемент с проверкой границы, back возвращает последний, size сообщает количество элементов.

Результат 4 9 3 означает: первое число 4, последнее 9, всего три числа. Индексы начинаются с нуля. Обращение at(3) здесь ошибочно: четвёртого элемента нет. Для пустого vector нельзя использовать back.

Пример (cpp):
```
#include <iostream>
#include <vector>

int main() {
    std::vector<int> readings{4, 7};
    readings.push_back(9);
    std::cout << readings.at(0) << " " << readings.back() << " " << readings.size() << "\n";
}

```
Результат: 4 9 3

Частая ошибка: Добавление элементов может перераспределить память vector и сделать прежние указатели на элементы недействительными.

## std::map: доступ по ключу · cpp.map

Ассоциативный контейнер связывает ключ с одним значением.

std::map связывает ключи со значениями. Вместо номера элемента можно искать данные по имени: например, заряд конкретного поста.

В примере ключ "beacon" связан с числом 3. Поиск find("kiln") не находит записи и возвращает специальную позицию end. Сравнение с end даёт true, то есть «запись не найдена». Для существующего beacon вызов at возвращает 3.

Такой поиск позволяет отличить отсутствие записи от нулевого заряда. Оператор [] ведёт себя иначе: при отсутствующем ключе он добавляет запись со значением по умолчанию. Для проверки наличия записи лучше сначала использовать поиск.

Пример (cpp):
```
#include <iostream>
#include <map>
#include <string>

int main() {
    std::map<std::string, int> charge{{"beacon", 3}};
    auto found = charge.find("kiln");
    std::cout << std::boolalpha << (found == charge.end()) << "\n";
    std::cout << charge.at("beacon") << "\n";
}

```
Результат: true
3

Частая ошибка: Проверка отсутствия через charge["kiln"] может сама добавить kiln со значением 0.

## std::set и уникальность · cpp.set

set хранит по одному элементу для каждого эквивалентного ключа.

std::set хранит уникальные значения в упорядоченном виде. Он полезен для набора уже обработанных номеров, когда повторная запись не должна создавать второй элемент.

В примере указаны 7, 7 и 1. Две семёрки дают один уникальный элемент, поэтому size возвращает 2. Метод contains(7) проверяет наличие семёрки и возвращает true. Получается вывод 2 true.

Множество отвечает на вопрос о принадлежности, но не сохраняет количество повторов. Если важно знать, сколько раз встретился номер, понадобится отдельный счётчик, например значение в map.

Пример (cpp):
```
#include <iostream>
#include <set>

int main() {
    std::set<int> ids{7, 7, 1};
    std::cout << ids.size() << " " << std::boolalpha << ids.contains(7) << "\n";
}

```
Результат: 2 true

Частая ошибка: Нельзя менять ключ set через итератор так, чтобы нарушить порядок контейнера.

## Перебор и const-ссылка · cpp.iteration

Range-for позволяет читать элементы без ручного индекса.

Когда нужно обработать все элементы последовательности, можно перебирать сами значения, не вычисляя их индексы вручную. Это делает намерение цикла заметнее.

В примере цикл берёт 2, затем 4, затем 6 и прибавляет их к total. Сумма меняется с 0 до 2, затем до 6 и до 12. После обхода выводится 12.

В записи const auto& слово auto просит компилятор определить тип элемента, & даёт доступ по ссылке без отдельной копии, а const запрещает менять элемент через эту ссылку. Такая форма удобна для чтения, особенно когда элементы больше простого числа.

Пример (cpp):
```
#include <iostream>
#include <vector>

int main() {
    std::vector<int> readings{2, 4, 6};
    int total{0};
    for (const auto& value : readings) { total += value; }
    std::cout << total << "\n";
}

```
Результат: 12

Частая ошибка: Не меняйте структуру vector во время такого перебора: его внутренние итераторы могут стать недействительными.

## Исключения и граница обработки · cpp.errors

Исключение передаёт ошибку к подходящему обработчику.

У списка readings один элемент. Его индекс равен 0: отсчёт начинается с нуля. Обращение at(2) просит третий элемент, которого нет. Метод at проверяет границу и сообщает об ошибке исключением std::out_of_range.

Инструкции внутри try выполняются обычным образом, пока не возникнет исключение. Тогда выполнение переходит в подходящий catch. В примере он выводит invalid index — «неверный индекс». Число из списка не выводится: обращение к нему не удалось.

Обработчик должен объяснить проблему или выполнить осмысленное восстановление. Пустой catch скроет ошибку, но не сделает индекс правильным.

Пример (cpp):
```
#include <iostream>
#include <vector>
#include <stdexcept>

int main() {
    std::vector<int> readings{3};
    try {
        std::cout << readings.at(2) << "\n";
    } catch (const std::out_of_range&) {
        std::cout << "invalid index\n";
    }
}

```
Результат: invalid index

Частая ошибка: Исключение не защищает от любого неопределённого поведения: выход за границы через [] не обязан выбрасывать его.

## Разбор числа и проверка диапазона · cpp.validation

Разбор должен потребить весь ввод, затем подтвердить допустимое значение.

Прежде чем использовать введённое значение, нужно проверить и его запись, и допустимый диапазон. Строка 22x начинается с числа, но целиком номером порта не является.

std::from_chars пытается разобрать число. result.ec сообщает, была ли ошибка разбора, а result.ptr указывает, где разбор остановился. Для 22x он остановится перед x. Поэтому недостаточно увидеть, что начальные цифры прочитаны: нужно проверить, что разобрана вся строка.

Проверка valid также ограничивает порт диапазоном от 1 до 65535. Все условия соединены через &&: каждое должно выполняться. В примере выводится false — «проверка не пройдена», потому что в строке остался символ x.

Пример (cpp):
```
#include <iostream>
#include <string>
#include <charconv>
#include <system_error>

int main() {
    std::string text{"22x"};
    int port{};
    auto result = std::from_chars(text.data(), text.data() + text.size(), port);
    bool valid = result.ec == std::errc{} && result.ptr == text.data() + text.size() && port >= 1 && port <= 65535;
    std::cout << std::boolalpha << valid << "\n";
}

```
Результат: false

Частая ошибка: Не проверяйте лишь result.ec: частично разобранный ввод всё ещё может содержать хвост.

## Потоки и проверка чтения · cpp.streams

Поток объединяет источник данных и состояние чтения.

Поток позволяет читать данные последовательно, по мере их поступления. Для проверки разбора можно использовать std::istringstream: он читает из строки в памяти, поэтому файл создавать не нужно.

В примере строка содержит "4 7 9". Операция input >> value пытается прочитать очередное целое число. Пока чтение успешно, цикл прибавляет его к total. После третьего числа данные заканчиваются, условие цикла становится ложным.

Сумма равна 20. Если вместо числа попадётся неподходящий текст, чтение тоже остановится. Поэтому в настоящем обработчике важно различать нормальный конец данных и ошибку формата, а не считать любой остановившийся цикл успешным разбором.

Пример (cpp):
```
#include <iostream>
#include <sstream>

int main() {
    std::istringstream input{"4 7 9"};
    int value{}, total{};
    while (input >> value) { total += value; }
    std::cout << total << "\n";
}

```
Результат: 20

Частая ошибка: while (!input.eof()) не проверяет успешность следующего чтения и часто обрабатывает лишнее старое значение.

## Структуры и связанные данные · cpp.structs

struct даёт имя записи из нескольких полей.

Структура собирает связанные поля в одну запись. Вместо отдельных переменных с похожими именами можно описать объект: например, пост с именем и зарядом.

Объявление struct Station задаёт два поля: name типа std::string и charge типа int. Запись Station post{"beacon", 3} создаёт конкретный объект и заполняет эти поля в порядке объявления.

Доступ через точку выбирает поле объекта: post.name даёт beacon, post.charge даёт 3. Поэтому выводится beacon 3. Структура хранит данные, но сама по себе не проверяет, допустим ли заряд. Для внешнего ввода такую проверку нужно организовать отдельно.

Пример (cpp):
```
#include <iostream>
#include <string>

struct Station {
    std::string name;
    int charge;
};

int main() {
    Station post{"beacon", 3};
    std::cout << post.name << " " << post.charge << "\n";
}

```
Результат: beacon 3

Частая ошибка: Байтовое представление структуры нельзя бездумно записывать как переносимый сетевой формат: есть выравнивание и различия платформ.

## Шаблоны и вывод типа · cpp.templates

Шаблон описывает одну операцию для разных подходящих типов.

Иногда одна операция нужна для разных типов. Шаблон позволяет описать общий способ вычисления, а компилятор создаст подходящую версию для используемых типов.

В функции larger буква T обозначает тип параметров и результата. Выражение a > b ? a : b читается так: если a больше b, выбрать a, иначе выбрать b.

Вызов larger(3, 7) работает с целыми и возвращает 7. Вызов larger(1.5, 2.5) работает с дробными числами и возвращает 2.5. Тип должен поддерживать сравнение >. Шаблон не означает, что функция сможет работать с любыми данными без ограничений.

Пример (cpp):
```
#include <iostream>

template<class T>
T larger(T a, T b) {
    return a > b ? a : b;
}

int main() {
    std::cout << larger(3, 7) << "\n";
    std::cout << larger(1.5, 2.5) << "\n";
}

```
Результат: 7
2.5

Частая ошибка: Не усложняйте маленькую функцию шаблоном, если ей действительно нужен один конкретный тип.

## Тесты и граничные значения · cpp.testing

Проверка на границе защищает смысл условия.

Тест проверяет ожидаемое поведение программы. Хорошая проверка защищает конкретное правило: например, при точном совпадении заряда и расхода энергии хватает.

Функция enough возвращает результат сравнения charge >= cost. Первый assert проверяет случай 3 и 3, второй — что для 2 и 3 ответа «хватает» нет. Если условие assert ложно, программа аварийно завершает проверку. В примере оба условия верны, поэтому выводится checks passed — «проверки пройдены».

Замена >= на > нарушит первый тест. Это и есть полезная граница. assert применяют для внутренних проверок; в сборке с NDEBUG они могут быть отключены, поэтому проверять ими внешний ввод нельзя.

Пример (cpp):
```
#include <iostream>
#include <cassert>

bool enough(int charge, int cost) { return charge >= cost; }

int main() {
    assert(enough(3, 3));
    assert(!enough(2, 3));
    std::cout << "checks passed\n";
}

```
Результат: checks passed

Частая ошибка: Не помещайте обязательные действия внутрь assert: в сборке с NDEBUG они могут вообще не выполниться.

## Алгоритмы стандартной библиотеки · cpp.algorithms

Готовый алгоритм делает намерение заметным.

Для распространённых действий стандартная библиотека предоставляет готовые алгоритмы. Они помогают выразить задачу через нужный результат: посчитать, найти, отсортировать.

std::count_if проходит по элементам от readings.begin() до readings.end() и считает те, для которых условие верно. Запись [](int x) { return x > 0; } — небольшая безымянная функция, которая проверяет положительность числа.

Для набора 7, -1, 3, 7 подходят три элемента, поэтому выводится 3. Две семёрки учитываются отдельно: мы считаем записи, а не уникальные значения. Исходный vector при этом не изменяется.

Пример (cpp):
```
#include <iostream>
#include <vector>
#include <algorithm>

int main() {
    std::vector<int> readings{7, -1, 3, 7};
    auto count = std::count_if(readings.begin(), readings.end(), [](int x) { return x > 0; });
    std::cout << count << "\n";
}

```
Результат: 3

Частая ошибка: Алгоритмы с требованиями к порядку, например binary_search, нельзя применять к неотсортированному диапазону.

## Владение ресурсом и RAII · cpp.raii

Ресурс привязывается ко времени жизни владеющего объекта.

Если программа получила ресурс, нужно определить, кто отвечает за его освобождение. RAII — подход C++, при котором эта ответственность связана со сроком жизни объекта-владельца.

В примере std::make_unique<int>(7) создаёт целое число в динамической памяти и возвращает unique_ptr, который им владеет. Оператор * даёт доступ к самому числу, поэтому выводится 7.

Когда charge выходит из области видимости, его unique_ptr освобождает память автоматически. Вручную вызывать delete не требуется. Обычная ссылка или сырой указатель такой ответственности не выражают, поэтому наличие адреса ещё не говорит, кто и когда освободит ресурс.

Пример (cpp):
```
#include <iostream>
#include <memory>

int main() {
    auto charge = std::make_unique<int>(7);
    std::cout << *charge << "\n";
}

```
Результат: 7

Частая ошибка: Не вызывайте delete для объекта, которым владеет unique_ptr. Передачу владения выражают через std::move.

## Потоки, mutex и общее состояние · cpp.concurrency

Доступ нескольких потоков к общей записи должен быть согласован.

Несколько потоков могут выполнять работу одновременно и обращаться к общим данным. Если изменения должны быть согласованы, их защищают одним правилом доступа.

В примере два потока запускают worker. Каждый двадцать раз увеличивает total. std::mutex — замок, а lock_guard удерживает его до конца текущего блока и автоматически освобождает при выходе. Поэтому одновременного изменения total в защищённых участках нет.

a.join() и b.join() ожидают завершения обоих потоков. После сорока увеличений выводится 40. Запись [&] позволяет worker обращаться к окружающим переменным по ссылке; они должны оставаться живы, пока потоки ими пользуются.

Пример (cpp):
```
#include <iostream>
#include <mutex>
#include <thread>

int main() {
    int total{0};
    std::mutex mutex;
    auto worker = [&] {
        for (int i{0}; i < 20; ++i) {
            std::lock_guard<std::mutex> guard(mutex);
            ++total;
        }
    };
    std::thread a(worker), b(worker);
    a.join();
    b.join();
    std::cout << total << "\n";
}

```
Результат: 40

Частая ошибка: Само наличие mutex ничего не гарантирует, если часть доступов к данным проходит без него.

## Абсолютный и относительный путь · sys.paths

Относительный путь начинается от текущей папки, абсолютный — от корня.

Путь указывает расположение файла или папки. Абсолютный путь начинается от корня: /var/log обозначает одно расположение независимо от текущей папки. Относительный путь отсчитывается от того места, где вы сейчас.

В примере текущая папка — /var/tmp. Две точки в ../log означают переход к родительской папке /var, после чего выбирается log. Поэтому здесь ../log и /var/log ведут в одно место.

Точка обозначает текущую папку. Перед использованием короткого пути проверяйте pwd: после перехода в другую папку тот же относительный путь может указывать уже на другой файл.

Пример (text):
```
Текущая папка: /var/tmp
../log → /var/log
/var/log → /var/log
```
Результат: Обе записи здесь указывают на одну папку.

Частая ошибка: Корень / и домашняя папка пользователя — разные места.

## Код завершения команды · sys.exit

Текст ответа и признак успешного завершения дополняют друг друга.

После выполнения программа может сообщить код завершения — небольшое число, обозначающее итог. В Unix-подобных системах ноль обычно означает успех, а ненулевое значение — ошибку или иной особый результат по правилам команды.

В примере запрос статуса выполнен успешно, но полученный статус — inactive: служба не работает. Это не противоречие. Команда смогла получить сведения, а сведения говорят об остановке службы.

Поэтому проверяйте и успешность запроса, и его содержимое. Сообщение «статус получен» не равно сообщению «всё исправно». Значения конкретных кодов нужно читать в описании команды.

Пример (text):
```
Запрос статуса: выполнен успешно
Состояние службы: inactive
```
Результат: Запрос успешен, служба при этом не работает.

Частая ошибка: Не считайте отсутствие красного текста доказательством успеха.

## Права доступа к файлу · sys.permissions

Чтение, запись и выполнение — отдельные полномочия.

Права доступа определяют, кому разрешено читать, менять или выполнять файл. В Linux базовые права отдельно задаются владельцу, группе и остальным пользователям.

В схеме rw- у владельца означает чтение и запись. r-- у группы разрешает только чтение. --- у остальных не даёт этих разрешений. Буква x у обычного файла относится к выполнению, а у папки — к возможности прохода по пути.

Права папок тоже участвуют в доступе к файлу: знать его имя недостаточно. Реальная система может применять дополнительные правила. Схема показывает базовый случай для обычного доступа, а не все механизмы защиты Linux.

Пример (text):
```
Владелец: rw-
Группа: r--
Остальные: ---
```
Результат: Владелец может читать и менять файл; группа — только читать.

Частая ошибка: Не выдавайте всем полный доступ только ради исчезновения ошибки.

## Окружение процесса · sys.environment

Переменные окружения передаются процессу как часть его запуска.

Окружение процесса — набор именованных значений, которые программа получает при запуске. Через них можно передать режим работы или путь к настройкам, не меняя исходный код.

В примере терминал имеет MODE=debug, а уже работающая служба — MODE=release. Изменение MODE в терминале не переписывает окружение прежнего процесса: это отдельные наборы данных.

Дочерний процесс обычно получает копию окружения при запуске. Например, PATH помогает находить исполняемые программы по имени. Поэтому при диагностике нужно выяснить, какие значения получила именно нужная программа и когда она была запущена.

Пример (text):
```
Терминал: MODE=debug
Уже запущенная служба: MODE=release
```
Результат: Смена MODE в терминале не меняет прежний процесс автоматически.

Частая ошибка: Не храните секрет в окружении без учёта того, кто может прочитать данные процесса.

## Сигналы и штатное завершение · sys.signals

Сигнал передаёт процессу уведомление, а не гарантирует мгновенный результат.

Сигнал — способ уведомить процесс о событии. Например, можно попросить программу завершиться. Штатное завершение даёт ей возможность сохранить нужные данные и закрыть ресурсы.

SIGTERM по умолчанию завершает процесс; программа может установить обработчик и подготовиться к выходу. SIGKILL нельзя перехватить пользовательским обработчиком, поэтому приложение не сможет выполнить собственные завершающие действия.

В примере старый PID завершился, но менеджер службы создал новый процесс. Значит, остановка одного исполнителя не выключила механизм восстановления. Для устойчивого результата нужно разобраться с управляющей службой и проверить её состояние.

Пример (text):
```
PID 712 получил запрос завершения
Менеджер заметил остановку
Новый экземпляр имеет другой PID
```
Результат: Исчезновение старого PID не означает остановку механизма восстановления.

Частая ошибка: Не путайте процесс, экземпляр службы и политику её запуска.

## Журнал событий и время · sys.logs

Журнал помогает восстановить последовательность, но остаётся источником с ограничениями.

Журнал событий — последовательность записей о том, что происходило в системе. Он помогает восстановить ход событий, когда смотреть на них в реальном времени уже поздно.

В примере сначала включилось охлаждение, затем датчик зарегистрировал снижение температуры. Порядок согласуется с предположением, что охлаждение работает, но двух строк недостаточно, чтобы доказать причину: мог измениться и другой фактор. Полезная запись содержит время, источник, событие и измеренный результат.

Часы разных устройств могут расходиться, а запись может потеряться. Поэтому отсутствие строки не доказывает отсутствие события. Журналы сопоставляют с текущими показаниями и другими источниками. Сообщение «команда принята» тоже не равно подтверждению, что действие завершено.

Пример (text):
```
12:00:01 climate: охлаждение включено
12:00:10 sensor: температура снизилась с 30 до 29 °C
```
Результат: Записи позволяют выдвинуть объяснение; для вывода нужны дополнительные наблюдения.

Частая ошибка: Последняя строка файла не обязательно описывает текущее состояние.

## Служба и политика восстановления · sys.service-policy

Желаемое поведение менеджера живёт дольше отдельного PID.

Служба — способ управлять запуском программы: задать команду, условия работы и поведение при сбое. Текущее выполнение и правило запуска существуют отдельно. Если исполнитель завершился, правило может потребовать запустить замену.

В systemd описание службы хранится в unit-файле с расширением .service. Например, в папке /etc/systemd/system могут лежать локальные настройки. Description описывает назначение, ExecStart — запускаемую программу, Restart — правило перезапуска. Имя файла помогает найти службу, но её роль выясняют по содержимому и наблюдаемому поведению.

stop останавливает службу сейчас. disable убирает её обычное включение в автозапуск; работающий экземпляр от этого не обязан завершиться. В схеме автозапуск выключен, но процесс продолжает работать — это допустимое сочетание.

В настоящем systemd есть и другие способы запуска: вручную, через зависимости или сокеты. Поэтому disable не является запретом всех будущих запусков. Операцию выбирают по нужному результату.

Пример (text):
```
Автозапуск выключен
Процесс ещё работает
→ Нужна отдельная остановка и повторная проверка
```
Результат: Текущее выполнение и будущая активация — две независимые проверки.

Частая ошибка: Зелёный результат disable не означает, что процесс уже завершён.

## Имя узла и DNS · net.dns

Имя помогает найти адрес, но не заменяет проверку собеседника.

DNS помогает искать сетевые сведения по имени. Например, по имени сервера можно получить его адрес, вместо того чтобы хранить адрес вручную в каждой программе.

В примере core.example связан с 10.17.0.99. TTL — срок, в течение которого ответ можно хранить в кэше, то есть использовать сохранённую копию. Здесь он равен 60 секундам.

Если запись изменится, ранее сохранённые ответы не исчезнут мгновенно. Поэтому разные клиенты некоторое время могут видеть разные адреса. Получение адреса — только этап подключения: доступность службы и проверка её личности выполняются отдельно.

Пример (text):
```
core.example → 10.17.0.99
TTL: 60 секунд
```
Результат: Клиент может использовать кэшированный ответ в пределах его срока.

Частая ошибка: Не считайте название компьютера секретом или надёжным удостоверением его личности.

## Порт и служба · net.ports

Адрес выбирает сетевой узел, порт — конечную точку транспорта на нём.

Порт помогает направить сетевой обмен нужной программе на узле. На одном компьютере могут одновременно работать удалённый доступ, веб-сервис и другие приложения.

В схеме один адрес 10.17.0.99 используется с TCP-портами 22 и 443. Это разные конечные точки. Полный ориентир включает адрес, транспортный протокол и порт: номера TCP и UDP принадлежат разным пространствам.

Привычный номер — соглашение, а не доказательство того, что за ним находится нужная программа. Для диагностики проверяйте фактическую службу и её ответ, а не только совпадение номера.

Пример (text):
```
10.17.0.99 : TCP : 22
10.17.0.99 : TCP : 443
```
Результат: Это две разные конечные точки на одном узле.

Частая ошибка: Не путайте доступность узла с доступностью конкретной службы.

## TCP: поток байтов · net.tcp

TCP даёт упорядоченный поток, а границы сообщений задаёт приложение.

TCP передаёт упорядоченный поток байтов между сторонами соединения. Приложение получает данные порциями, но границы этих порций не обязаны совпадать с границами отправленных сообщений.

В примере отправлены строки READY и STOP с переводами строк. Первое чтение вернуло только REA, второе — остаток первой строки и всю вторую. Программа должна накопить данные, найти разделители и восстановить обе записи.

Поэтому протокол приложения должен объяснять, где заканчивается сообщение: длиной, разделителем или другим правилом. Одно успешное чтение само по себе ещё не означает получение полного сообщения.

Пример (text):
```
Отправлено: [READY\n][STOP\n]
Первое чтение: REA
Второе чтение: DY\nSTOP\n
```
Результат: Парсер должен восстановить сообщения независимо от порций чтения.

Частая ошибка: Не интерпретируйте нулевое чтение как обычный пустой пакет данных.

## TLS и проверка собеседника · net.tls

Шифрование полезно вместе с проверкой личности другой стороны.

TLS защищает данные при передаче и помогает проверить собеседника. Шифрование скрывает содержимое обмена от посторонних на пути, а проверка сертификата связывает соединение с ожидаемым сервером.

В схеме клиент обращается к core.example, но сертификат выдан для другого имени. Соединение нужно отклонить: наличие шифрования не исправляет несовпадение личности.

Проверка включает доверенную цепочку сертификатов, имя и срок действия по принятой политике. TLS не делает данные сервера автоматически правдивыми и не выдаёт пользователю права на любые действия.

Пример (text):
```
Имя запроса: core.example
Имя сертификата: другое
Решение: отклонить соединение
```
Результат: Наличие шифрования не исправляет несовпадение личности.

Частая ошибка: Не переносите выключенную проверку из временного эксперимента в рабочую конфигурацию.

## Таймаут и бюджет попыток · net.timeout

Ожидание должно иметь ограничение по времени и понятный результат.

Таймаут ограничивает, сколько программа ждёт завершения операции. Без него недоступный узел может удерживать работу неопределённо долго. Общий бюджет времени ограничивает уже весь сценарий, включая повторные попытки.

В примере на работу выделено пять секунд. Первая попытка заняла две, значит следующей остаётся не больше трёх. Бюджет не начинается заново при каждом сбое.

Отсутствие ответа не доказывает, что действие не выполнено: ответ мог потеряться после обработки. Перед повтором важной команды выясните, безопасно ли выполнить её дважды, и предусмотрите способ проверки результата.

Пример (text):
```
Общий бюджет: 5 с
Первая попытка: 2 с
Вторая попытка: максимум оставшиеся 3 с
```
Результат: Бюджет не начинается заново после каждого сбоя.

Частая ошибка: Не применяйте бесконечный повтор как универсальное лечение сетевой ошибки.

## Граница доверия · sec.trust

Полученные данные ещё не заслужили право управлять системой.

Граница доверия — место, где данные переходят из чужой области в вашу. Это может быть сетевое сообщение, загруженный файл или текст в поле ввода. Даже знакомое имя отправителя само по себе ничего не доказывает.

Представьте ремонтного дрона, который получает сообщение «поднять груз». Сначала он разбирает формат: есть ли номер операции и масса. Затем проверяет отправителя, его право управлять подъёмником и срок действия запроса. Правильно написанный приказ может оказаться чужим или устаревшим.

В схеме ниже проверки идут до действия. Если хотя бы одна не пройдена, система отказывает и сохраняет причину. Проверять нужно там, где команда действительно исполняется: проверку в окне отправителя можно обойти.

Пример (text):
```
Запрос на подъём груза
→ Формат понятен?
→ Отправитель подтверждён?
→ Подъём разрешён и запрос ещё актуален?
→ Выполнить или отказать
```
Результат: До выполнения нужно пройти все необходимые проверки.

Частая ошибка: Надпись «внутренняя сеть» не делает все сообщения в ней доверенными.

## Минимальные полномочия · sec.privilege

Каждому участнику — столько доступа, сколько нужно для работы.

Полномочие — разрешение выполнить действие: прочитать файл, изменить настройку, запустить привод. Принцип минимальных полномочий предлагает выдавать только необходимые разрешения и только на нужное время.

Сервис прогноза погоды должен читать датчики. Право стирать архив ему ни к чему. Если в сервисе найдётся ошибка, ограниченный доступ уменьшит возможный ущерб. Администраторские права «на всякий случай» превращают маленькую поломку в большую.

В примере обязанности разделены между тремя участниками. Для временного ремонта можно выдать отдельное разрешение со сроком. После работы его отзывают; оставленный аварийный доступ со временем становится обычной дырой.

Пример (text):
```
Метеосервис: читать датчики
Архиватор: добавлять записи в архив
Ремонтник: менять настройку до конца ремонта
```
Результат: Разрешения привязаны к задаче, ресурсу и при необходимости сроку.

Частая ошибка: Проверяйте и права служебных программ: они тоже могут ошибаться или быть скомпрометированы.

## Аутентификация: кто перед вами · sec.authn

Имя — заявление. Аутентификация проверяет доказательство.

Аутентификация отвечает на вопрос «кто обращается?». Логин только называет участника. Пароль, ключ или другой подходящий способ подтверждения помогает проверить, что обращается именно он.

У складского робота может быть собственная машинная учётная запись. Сервер проверяет доказательство владения её ключом, а не верит полю «я робот склада». Украденный ключ позволяет выдавать себя за владельца, поэтому его защищают и при утечке заменяют.

Успешная проверка личности ещё не разрешает любое действие. После неё система отдельно проверяет полномочия. Это следующий вопрос: «что этому участнику можно сделать с этим объектом?».

Пример (text):
```
Заявлено: робот склада
Доказательство владения ключом: проверено
Следующий шаг: проверить разрешение на операцию
```
Результат: Личность подтверждена; решение о доступе ещё впереди.

Частая ошибка: Не путайте подтверждённую личность с неограниченным доступом.

## Авторизация: что разрешено · sec.authz

Знать, кто перед вами, мало: нужно проверить его права.

Авторизация решает, разрешено ли участнику выполнить конкретное действие над конкретным объектом. Сотрудник обсерватории может читать показания телескопа, но не менять направление его движения.

В примере чтение разрешено, поворот — нет. Решение зависит от правил: роли сотрудника, объекта, времени смены и других нужных условий. Разрешение на один телескоп не распространяется автоматически на все остальные.

Право проверяют при каждой операции на стороне системы, которая её выполняет. Скрытая кнопка не защищает действие: запрос можно отправить другим способом. Если подходящего разрешения нет, безопасная исходная позиция — отказ.

Пример (text):
```
Сотрудник + читать показания + телескоп A → разрешено
Сотрудник + повернуть + телескоп A → отказ
```
Результат: Один участник может иметь разные права на разные действия.

Частая ошибка: Не храните решение «доступ разрешён навсегда»: права и обстоятельства могут измениться.

## Проверка формата и смысла · sec.input

Понятный формат ещё не означает допустимое значение.

Проверка ввода начинается с формы данных и продолжается их смыслом. «9000» можно разобрать как целое число. Но если допустимая скорость тележки от 0 до 5, такое значение всё равно нельзя принять.

Сначала ограничивают размер сообщения, затем проверяют нужные поля, типы и диапазоны. Дальше — связи между значениями: время завершения не может быть раньше начала. И только после этого данные используют в операции.

Проверка должна происходить до изменения состояния. Иначе программа сначала запустит тележку, а затем вежливо сообщит об ошибке. Лучше короткий отказ с понятной причиной, чем попытка молча угадать намерение отправителя.

Пример (text):
```
speed: 9000
Формат: целое число
Допустимо: 0..5
Решение: отклонить
```
Результат: Синтаксически верное значение нарушает смысловое ограничение.

Частая ошибка: Проверка диапазона не заменяет проверку права управлять устройством.

## Секреты и их жизненный цикл · sec.secrets

Пароль или ключ нужно уметь не только выдать, но и отозвать.

Секрет — данные, знание которых помогает получить доступ: пароль, токен, закрытый ключ. Их не кладут в общедоступный код, снимки экрана и журналы ошибок. Даже случайная публикация может быть достаточна для утечки.

У секрета есть жизненный цикл: выдача, использование, замена и отзыв. Например, ремонтная программа получает временный токен с правом читать один архив. Когда работа закончена, токен перестаёт действовать.

Если ключ попал к постороннему, удалить сообщение с ним недостаточно: копия могла сохраниться. Старый ключ отзывают, проверяют последствия и выдают новый. В примере новая выдача не возвращает силу старому ключу.

Пример (text):
```
Выдан ключ → ограничен срок
Подозрение на раскрытие → отзыв
Новый ключ → новая выдача
```
Результат: Смена включает прекращение действия старого ключа.

Частая ошибка: Звёздочки в интерфейсе скрывают текст от взгляда, но не защищают место его хранения.

## Целостность и происхождение · sec.integrity

Совпадение хеша проверяет содержимое, но само не подтверждает автора.

Хеш — короткое значение, вычисленное из данных. Для подходящего криптографического хеша даже небольшое изменение файла с огромной вероятностью даст другое значение. Так можно сравнить полученный файл с доверенным эталоном.

Представьте архив чертежей и лежащую рядом записку с его хешем. Если нарушитель заменил и архив, и записку, сравнение сойдётся. Поэтому важно, откуда взялся эталон: он должен прийти по доверенному пути.

Цифровая подпись решает ещё одну задачу — связывает данные с ключом подписавшего. Для проверки нужен доверенный открытый ключ. Даже действительная подпись не обещает, что программа полезна и безопасна: она подтверждает более узкое свойство.

Пример (text):
```
Файл A → хеш H
Полученный файл → хеш H
Дополнительно: откуда получен сам эталон H?
```
Результат: Совпадение с недоверенным эталоном не подтверждает автора.

Частая ошибка: Обычная контрольная сумма и цифровая подпись — разные инструменты.

## Аудит действий · sec.audit

Хорошая запись отвечает: кто, что, с чем и с каким результатом сделал.

Аудит — журнал значимых действий и решений о доступе. Он помогает восстановить последовательность событий: кто запросил операцию, какой объект затронут, когда это произошло и чем закончилось.

В примере request — номер запроса, subject — участник, action — действие, result — итог проверки. Один номер запроса в нескольких сервисах помогает связать записи в общую историю. Время полезно, но часы разных машин могут расходиться.

«Доступ разрешён» и «операция выполнена» — разные события. Оба стоит различать в журнале. Сам журнал защищают от подмены, задают срок хранения и не превращают в склад паролей. Иначе расследование создаст новую утечку.

Пример (text):
```
request=map-42
subject=cartographer
action=read-map
result=allowed
```
Результат: Разрешение выдано; результат самого чтения можно записать отдельным событием.

Частая ошибка: Не записывайте успех операции только потому, что пользователь нажал кнопку.

## Сегментация и границы связи · sec.segmentation

Разделение сети ограничивает, куда сможет распространиться проблема.

Сегментация делит сеть на области с разными правилами связи. Гостевой терминал, архив и оборудование могут находиться в одном здании, но это не повод разрешать им любые соединения друг с другом.

В примере читательский терминал обращается к архиву, а к приводу тележки — нет. Между областями разрешают только нужные направления и службы. Если терминал взломают, такая граница уменьшит число доступных целей.

Разрешённый канал всё равно требует проверки данных и прав. А разрыв соединения не отменяет уже полученную работу: автономное устройство может её продолжить. Сеть ограничивает доставку сообщений; поведение получателя определяется ещё и его собственными правилами.

Пример (text):
```
Читательский терминал → архив: разрешено
Читательский терминал → привод тележки: запрещено
Ремонтный пост → привод: отдельное разрешение
```
Результат: Связь открыта для нужных задач, а не для всех участников сразу.

Частая ошибка: Сегментация уменьшает область риска, но не заменяет защиту самих приложений.

## Повтор старой команды · sec.replay

Старый подлинный запрос тоже может причинить вред.

Атака повтором — повторная отправка ранее допустимого сообщения. Нарушителю не обязательно подделывать подпись: иногда достаточно ещё раз предъявить старый приказ, например на выдачу груза.

Получатель может проверять срок действия, номер операции и версию правил. Уже выполненный номер сохраняют, чтобы повтор не выдал второй груз. Для некоторых запросов вместо ошибки удобно вернуть прежний результат — это должно быть заранее определено.

В примере сообщение относится к версии 8, а действуют правила версии 9. Получатель проверяет, допустимо ли исполнение по старым правилам. Одна отметка времени задачу не решает: важны точность часов, хранение принятых номеров и поведение после перезапуска.

Пример (text):
```
Команда C42: версия 8
Текущая версия политики: 9
Решение: проверить актуальность и отклонить устаревшее действие
```
Результат: Подлинность отправителя и свежесть команды проверяются отдельно.

Частая ошибка: Действительная подпись подтверждает происхождение сообщения, а не его актуальность.

## Зависимости и цепочка поставки · sec.supply

Чужая библиотека получает место внутри вашей программы.

Зависимость — готовый компонент, который использует программа: библиотека, инструмент сборки, образ. Он экономит работу, но его ошибки и полномочия становятся частью вашей системы.

В вымышленной мастерской обновили библиотеку печати этикеток. Установщик заодно попросил доступ ко всему диску. Для печати это лишнее: перед подключением компонента стоит понять, откуда он получен и зачем ему такие права.

Запись точной версии помогает повторить сборку. Проверка происхождения и содержимого снижает риск подмены. Обновления испытывают перед выпуском и готовят возврат к рабочему состоянию. Старая закреплённая версия тоже может содержать известную уязвимость — закрепление не отменяет обслуживание.

Пример (text):
```
Компонент: фиксированная версия
Источник: проверен
Полномочия: минимальны
Обновление: отдельная проверка
```
Результат: Имя пакета само по себе не доказывает его происхождение.

Частая ошибка: Знакомое название пакета не гарантирует, что перед вами нужный пакет из нужного источника.

## Сдерживание и независимая проверка · sec.incident

Сначала ограничить ущерб, затем разобраться и восстановить работу.

Инцидент — событие, которое нарушает безопасность или даёт основания подозревать нарушение. Например, архив неожиданно передаёт данные неизвестному получателю. Нужно остановить опасное воздействие, не уничтожив при этом полезные сведения о случившемся.

Изоляция подозрительного соединения может выиграть время. Журналы и другие следы помогают понять, какие данные и устройства затронуты. Сведения из другого источника проверяют местный вывод: один спокойный экран ещё не описывает всю систему.

После устранения причины сервис возвращают под наблюдением. Если необычная активность повторилась, первоначальное объяснение было неполным. Восстановление — проверяемый этап работы, а не просто снятие красного предупреждения.

Пример (text):
```
Сдержать → сохранить следы → проверить другие узлы → восстановить под наблюдением
```
Результат: Один зелёный статус не закрывает весь инцидент.

Частая ошибка: Массовое удаление файлов может уничтожить и причину, и сведения, необходимые для расследования.

## Память процесса · os.memory

Программа обращается к памяти по адресам, которые ей предоставляет ОС.

В памяти процесс держит значения, с которыми работает сейчас: числа, строки, изображения. Виртуальное адресное пространство — его собственная карта адресов. ОС и оборудование связывают её с памятью и проверяют права доступа.

Один и тот же виртуальный адрес у двух процессов не обязан указывать на одно физическое место. Поэтому обычная программа не может прочитать память соседа, просто угадав число. Совместный доступ организуют отдельно.

Неверное обращение к памяти может завершить процесс. А адрес из старого запуска нельзя надёжно использовать после перезапуска: расположение и время жизни данных изменились. Для долговременного хранения записывают сами данные и устойчивые идентификаторы объектов.

Пример (text):
```
Процесс A: адрес X
Процесс B: адрес X
→ Это не обязательно одна физическая память
```
Результат: Одинаковое число адреса не означает общий объект.

Частая ошибка: Адрес в памяти не подходит как постоянное имя объекта в файле сохранения.

## Стек и динамическое хранение · os.stack-heap

Данные должны существовать столько, сколько они нужны программе.

Когда функция вызывает другую функцию, программе нужно помнить, куда вернуться и какие вызовы ещё не завершены. Для этого обычно служит стек вызовов. С ним часто связано и хранение локальных данных, которые автоматически уничтожаются при выходе из своей области.

Динамическое хранение позволяет выделить память на срок, который не обязан совпадать с одним вызовом функции. Например, функция загружает карту, а программа использует её и после возврата. За освобождение памяти должен отвечать понятный владелец; в C++ это удобно поручать контейнерам и умным указателям.

Схема ниже показывает срок жизни автоматического локального объекта. Сохранённая ссылка не продлевает этот срок сама по себе. Это описание модели, а не обещание физического размещения каждой переменной: компилятор может хранить её в регистре или убрать совсем.

Пример (text):
```
Вызов функции → создан автоматический локальный объект
Выход из его области → объект уничтожен
Старая ссылка на него → использовать нельзя
```
Результат: Если данные нужны дольше, их время жизни нужно организовать отдельно.

Частая ошибка: Наличие старого адреса не означает, что объект по нему ещё существует.

## Время жизни и владение · os.lifetime

У ресурса должен быть понятный ответственный за завершение работы.

Ресурс — то, что программа получает и должна вовремя освободить: память, открытый файл, соединение. Владелец отвечает за его срок жизни. Другие части программы могут временно пользоваться ресурсом, не становясь владельцами.

Допустим, модуль открывает карту из файла и передаёт читателю доступ к ней. Пока читатель работает, карта должна существовать. Если владелец уничтожит её раньше, оставшаяся ссылка станет недействительной.

В примере доступ завершается до освобождения. Автоматическое управление памятью помогает с памятью, но не решает все задачи: файлы и соединения тоже нужно закрывать. Чёткое владение упрощает и успешный путь, и обработку ошибок.

Пример (text):
```
Создать → передать допустимый доступ → завершить использование → освободить
```
Результат: Освобождение должно происходить после последнего допустимого использования.

Частая ошибка: Два независимых владельца не должны каждый по-своему закрывать один и тот же ресурс.

## Файловый дескриптор · os.descriptors

Дескриптор — номер открытого ресурса, а не его вечное имя.

В Linux и похожих системах файловый дескриптор — небольшое неотрицательное число, через которое процесс обращается к открытому файлу, сокету или другому поддерживаемому ресурсу. ОС хранит соответствие между номером и открытым ресурсом.

В примере журнал получил номер 5. После закрытия этот номер свободен и может достаться совсем другому ресурсу. Запомнить число 5 на завтра — не способ снова открыть тот же журнал. Нужны имя ресурса и новое открытие.

Открытие может завершиться ошибкой, а чтение — вернуть меньше данных, чем запрошено. Поэтому проверяют результаты операций. Дескриптор закрывают, когда работа закончена, и больше не используют как действующий.

Пример (text):
```
Открыт журнал → fd 5
Закрыт fd 5
Открыт другой ресурс → снова fd 5
```
Результат: Одинаковый номер в разное время может обозначать разные ресурсы.

Частая ошибка: После закрытия старый номер может обозначать уже другой ресурс.

## Буфер, длина и вместимость · os.buffers

Вместимость буфера задаёт предел, длина — сколько данных действительно получено.

Буфер — область памяти для временного хранения данных. У него есть вместимость: больше этого объёма записывать нельзя. Длина сообщает, какая часть сейчас содержит полезные данные.

В примере выделено 1024 байта, но чтение принесло только 17. Разбирать нужно эти 17 байт. Остальная память не становится продолжением ответа. Сетевой ответ может прийти частями; их собирают по правилам формата сообщения.

Размер, указанный отправителем, тоже проверяют. Если сообщение обещает миллион байтов, а в нём их двадцать, доверять обещанию нельзя. Верхние пределы помогают защититься и от выхода за границы памяти, и от бессмысленного расхода ресурсов.

Пример (text):
```
Вместимость: 1024 байта
Получено: 17 байт
Разбирать: только эти 17 байт
```
Результат: Остальная память не стала частью сообщения.

Частая ошибка: Запрошенный объём чтения и фактически полученный объём могут различаться.

## Байты, текст и UTF-8 · os.encoding

Текст хранится как байты; кодировка объясняет, как их прочитать.

Кодировка связывает символы и последовательности байтов. В UTF-8 латинская буква A занимает один байт, кириллическая Я — два. Поэтому количество байтов не равно количеству букв.

В примере D0 AF — шестнадцатеричная запись двух байтов буквы Я. Если сетевое чтение принесло только D0, это ещё не полный символ. Декодер должен дождаться продолжения или корректно обработать неполные данные.

Даже видимый знак не всегда равен одной кодовой точке: буква с ударением может собираться из нескольких. Для обрезки текста и движения курсора нужны подходящие текстовые операции. Деление по произвольному номеру байта способно сломать строку.

Пример (text):
```
Текст: Я
UTF-8: D0 AF
Размер: 2 байта
```
Результат: Один показанный символ здесь занимает два байта.

Частая ошибка: Отображение текста с неверной кодировкой портит чтение, а не обязательно сам исходный файл.

## Порядок байтов · os.endianness

Два байта одного числа можно записать в разном порядке.

Число больше 255 может занимать несколько байтов. Порядок байтов определяет, какой из них хранится первым: старший в big-endian или младший в little-endian.

В примере 0x1234 — шестнадцатеричная запись числа. Его два байта — 12 и 34. Big-endian хранит их как 12 34, little-endian — как 34 12. Само число при правильном чтении не меняется.

Ошибка появляется, когда отправитель пишет в одном порядке, а получатель читает в другом. Поэтому формат файла или протокол заранее определяет ширину числа и порядок байтов. Пересылка сырого участка памяти без такого соглашения ненадёжна.

Пример (text):
```
Число: 0x1234
Big-endian: 12 34
Little-endian: 34 12
```
Результат: Два байта одинаковы как набор, но порядок влияет на интерпретацию.

Частая ошибка: Порядок байтов вашего компьютера не обязан совпадать с форматом файла или протокола.

## Процесс и поток · os.threads

Потоки выполняют разные части работы внутри одного процесса.

У потока свой ход выполнения и стек вызовов. Потоки одного процесса обычно разделяют память и другие ресурсы процесса. Например, один принимает сообщения, другой готовит изображение из полученных данных.

Общая память облегчает обмен, но требует согласования. Если один поток меняет список, пока другой его читает, результат может оказаться неверным; в некоторых языках нарушение правил доступа приводит к неопределённому поведению. Для координации используют средства синхронизации или передачу сообщений.

На нескольких ядрах потоки могут выполняться одновременно. Но больше потоков не означает быстрее: ожидание, общий ресурс и затраты на координацию могут съесть выигрыш. Отдельные процессы обычно дают более сильную границу изоляции, зато обмен между ними организуют отдельно.

Пример (text):
```
Процесс
├ поток A: свой стек
└ поток B: свой стек
Общие данные: требуют согласования
```
Результат: Второй поток не получает автоматически копию всех объектов.

Частая ошибка: Не обращайтесь к общим изменяемым данным без правил, подходящих для языка и используемых библиотек.

## Критическая секция и взаимная блокировка · os.synchronization

Связанные изменения должны быть видны другим потокам согласованно.

Синхронизация помогает потокам договориться о порядке работы. Мьютекс — один из инструментов: поток захватывает его перед доступом к защищённым данным и освобождает после. Остальные участники соблюдают то же правило.

Перевод десяти деталей между двумя складами состоит из списания и зачисления. Если защищать только одну половину, другой поток может увидеть несогласованные остатки. Защищают весь нужный набор операций — критическую секцию.

Взаимная блокировка возникает, если первый поток держит замок A и ждёт B, а второй держит B и ждёт A. Никто не может продолжить. Единый порядок захвата помогает избежать такой ситуации; освобождение замков должно происходить и при ошибке.

Пример (text):
```
Поток 1: держит A, ждёт B
Поток 2: держит B, ждёт A
```
Результат: Оба ждут ресурс, который не будет освобождён текущим ходом.

Частая ошибка: Долгая внешняя операция под замком может остановить всех, кто ждёт тот же ресурс.

## Конечный автомат состояний · os.state-machine

Состояния описывают режимы, переходы — допустимые изменения.

Конечный автомат — модель с набором состояний и правилами перехода между ними. Событие предлагает изменение, а условие определяет, разрешено ли оно сейчас. Так удобнее описывать устройство, чем набором несвязанных флагов.

Учебный пример: сервисный робот патрулирует, замечает препятствие и переходит в ожидание. Когда путь свободен, возвращается к движению. При отключении питания он переходит в Offline, а новые команды движения в этом состоянии не выполняет.

У перехода могут быть последствия: остановить мотор, сбросить таймер, записать событие. Их выполняют вместе со сменой режима. Явная модель помогает заметить невозможные сочетания — например, одновременно «без питания» и «активно едет».

Пример (text):
```
Движение + препятствие → Ожидание
Ожидание + путь свободен → Движение
Любой активный режим + нет питания → Offline
```
Результат: В Offline команда движения не переводит робота в активный режим без восстановления питания.

Частая ошибка: Отдельные флаги без общих правил легко разрешают противоречивые режимы.

## Образ и работающий контейнер · infra.image

Образ хранит исходное содержимое, контейнер выполняет работу.

Образ контейнера — подготовленный набор файлов и настроек, из которого создают контейнер. Сам образ не является работающей программой. Контейнер — отдельный экземпляр запуска со своей конфигурацией и изменяемым слоем данных.

Из одного образа можно запустить два экземпляра сервиса: A и B. Остановка A не останавливает B и не удаляет образ. При этом оба могут зависеть от общих внешних ресурсов, например базы данных.

Тег — удобное имя версии, которое может указывать на другое содержимое после обновления. Digest обозначает содержимое точнее. Для повторяемого запуска важны ещё параметры, секреты и подключённые данные: один и тот же образ не гарантирует одинаковое окружение.

Пример (text):
```
Один образ
→ экземпляр A
→ экземпляр B
```
Результат: Завершение A само по себе не останавливает B.

Частая ошибка: Имя тега не является обещанием неизменности его содержимого.

## Данные за пределами экземпляра · infra.volume

Рабочие данные могут пережить замену контейнера.

У контейнера есть собственный изменяемый слой. В Docker после остановки он остаётся у этого контейнера, но удаление контейнера удаляет и слой. Для данных, которые нужны после замены экземпляра, выбирают отдельное хранилище.

Том — управляемое хранилище, которое подключают в файловую систему контейнера. Архив карт можно держать в томе: новый экземпляр подключит его и получит прежние файлы. В примере меняется исполнитель, а не само хранилище.

Срок жизни и удаление тома задаются правилами используемой системы. Случайное удаление или порча данных всё равно возможны. Поэтому отдельное хранение дополняют правами доступа и резервными копиями. Том сохраняет данные между запусками, но не хранит автоматически их здоровую прошлую версию.

Пример (text):
```
Экземпляр заменён
Рабочие данные: в отдельном хранилище
Новый экземпляр подключает их заново
```
Результат: Перезапуск приложения не должен случайно стирать нужный архив.

Частая ошибка: Том не заменяет резервную копию: ошибка программы может испортить данные и в нём.

## Работает, готов и полезен · infra.health

Запущенный процесс ещё не обязательно готов выполнять полезную работу.

Проверка состояния задаёт конкретный вопрос о сервисе. В Kubernetes liveness помогает решить, нужно ли перезапустить контейнер, который перестал работать нормально. Readiness показывает, готов ли экземпляр принимать рабочий трафик сервиса.

Архив может уже отвечать на соединения, но ещё восстанавливать индекс. Он жив, однако выдавать карты пока не готов. В примере процесс есть, а readiness отрицательна: новые рабочие запросы не должны идти к этому экземпляру.

Проверки подбирают под задачу и ограничивают по времени. Один открытый порт не доказывает правильность данных. Для долгого старта есть startup probe, которая даёт запуску закончиться до обычных проверок liveness и readiness. Слишком агрессивные перезапуски способны только продлить сбой.

Пример (text):
```
Процесс есть: да
Готов принимать запросы: нет
Рабочий маршрут: не направлять сюда
```
Результат: Временно неготовый экземпляр не обязательно нужно немедленно уничтожать.

Частая ошибка: Ошибка readiness обычно убирает экземпляр из рабочего трафика, а не требует его немедленного перезапуска.

## Желаемое и наблюдаемое состояние · infra.desired

Контроллер пытается привести наблюдаемое состояние к заданному.

Желаемое состояние описывает результат: например, должны работать два экземпляра сервиса карт. Наблюдаемое состояние показывает, что существует сейчас. Контроллер периодически сравнивает одно с другим и предпринимает доступные действия.

В примере задано два экземпляра, а найден один. Контроллер создаёт недостающий. Если вручную удалить ещё один, но оставить прежнюю цель, он снова попытается восстановить количество. Для устойчивого изменения меняют и управляющее правило.

Принятая настройка не означает мгновенного результата. Запуск может ждать ресурсы или закончиться ошибкой. Поэтому после изменения наблюдают за фактическим состоянием и причиной расхождений. Контроллер не волшебник: он действует в пределах своих возможностей.

Пример (text):
```
Желаемое: 2
Наблюдаемое: 1
Действие контроллера: создать ещё 1
```
Результат: Потеря экземпляра и изменение политики — разные события.

Частая ошибка: Удаление одного исполнителя само по себе не отменяет правило его восстановления.

## Повтор с задержкой · infra.backoff

После временного сбоя полезнее подождать, чем атаковать сервис повторами.

Backoff — задержка перед следующей попыткой. При экспоненциальном росте она увеличивается, например с одной секунды до двух, затем до четырёх. Верхний предел не даёт паузе расти бесконечно, а общий бюджет ограничивает число попыток или время ожидания.

Представьте сто терминалов, которые одновременно потеряли архив. Если все повторят запрос ровно через секунду, нагрузка снова придёт залпом. Jitter добавляет случайную поправку к задержке и разносит попытки во времени.

Повтор безопасен не для любой операции. После тайм-аута неизвестно, успел ли сервер выдать груз: новая попытка может выдать его второй раз. Нужен идентификатор операции или другое правило обработки дубликатов. Ошибку отсутствия прав обычно не исправить ожиданием.

Пример (text):
```
Паузы: 1 с → 2 с → 4 с
Предел: 4 с
Общий бюджет: ограничен
```
Результат: Повторы перестают непрерывно нагружать неисправный узел.

Частая ошибка: План повторов должен иметь предел и понятный итог, когда попытки закончились.

## Резервная копия и восстановление · infra.backup

Резервная копия ценна, когда из неё получается восстановить нужные данные.

Резервная копия — отдельная сохранённая версия данных для восстановления после потери или порчи. Она отличается от простого дубликата, который тут же повторяет ошибочное удаление.

Нужно заранее решить, сколько последних изменений допустимо потерять и сколько времени можно восстанавливаться. Копия раз в сутки не вернёт события последнего часа. Для связанных данных нужен согласованный снимок: список выданных карт и остаток бумаги не должны относиться к разным моментам.

В учебной истории архивариус годами видел зелёный статус копирования. На тренировке выяснилось: ключ расшифрования остался только на сломанном компьютере. Поэтому проверяют не одну запись файла, а реальное восстановление, доступность ключей и совместимость формата.

Пример (text):
```
Согласованный снимок архива → отдельная копия
Проверка целостности → восстановление в отдельное место
Проверка: файлы читаются, связанные записи совпадают
```
Результат: Существование файла копии — только начало проверки восстановления.

Частая ошибка: Не перезаписывайте единственную здоровую копию повреждёнными данными.
