# Runtime execution — Designed, not implemented

Цель: настоящий синтаксис выбранного языка и одинаковый контракт задания независимо
от языка. Текущий первый срез проверяет виртуальные команды; он не исполняет программы.

Контракт: immutable snapshot устройств + узкие capabilities + параметры → result,
diagnostics, ограниченный stdout, proposed game events. Ответ включает run ID, версию
схемы и snapshot revision. Только модель проверяет события и меняет мир. Исполнитель
не получает ссылки Unity, путь сохранений или системный shell. Отмена/таймаут не должны
частично применять действия.

| Кандидат | Полезное свойство по первоисточнику | Что ещё требуется |
| --- | --- | --- |
| QuickJS → WASM | Встраиваемый движок JavaScript; можно исследовать сборку с минимальным API | Отдельный worker/process, лимиты памяти/interrupt, отсутствие std/os imports, тесты моста |
| Pyodide в module worker | Настоящий Python, асинхронное выполнение отдельно от UI | Проверить JS interop/сетевые API, объём поставки, блокировку imports и восстановление после terminate |
| Wasmtime, desktop helper | Явная WASM-граница и импортируемые возможности | Поддержка нужного языка, OS process isolation, лимиты, поставка и аудит; отдельный путь от Unity Web |

Это кандидаты, а не выбранные проверенные зависимости. Источники просмотрены 2026-11-06:
[QuickJS](https://bellard.org/quickjs/), [Pyodide worker](https://pyodide.org/en/stable/usage/webworker.html),
[Wasmtime security](https://docs.wasmtime.dev/security.html).

Первый spike должен запускать маленькую JavaScript-функцию над копией списка датчиков,
затем проходить негативные тесты из THREAT_MODEL. После этого — интеграция с одним
контроллером. Python остаётся следующим отдельным spike. Не обещать единый бинарный
runtime для Web/Desktop до фактических сборок и проверки поведения.

Код редактора и проверяющие developer scripts могут запускать собственные доверенные
примеры в инструментальной среде. Это не пользовательский runtime и не доказательство
безопасности игровых скриптов.
