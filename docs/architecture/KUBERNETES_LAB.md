# Финальный независимый контур — Planned

Финал должен проверять действие системы, а не факт отправки manifest. Два режима:
детерминированная симуляция кластера для всех платформ и добровольная настоящая
лаборатория для поддерживаемых desktop-систем. Сейчас не реализован ни один режим.
Игру нельзя рекламировать как запускающую Kubernetes на основании этой спецификации.

## Контракт защитных сервисов

| Компонент | Вход → выход | Проверяемый результат |
| --- | --- | --- |
| Event Ingest | События виртуального комплекса → нормализованные записи | Некорректная схема отклоняется, дубликат не меняет состояние дважды |
| Policy Engine | Событие + версия политики → allow/deny с причиной | Запрет на опасное управляющее действие с доказуемой причиной |
| Threat Analyzer | Последовательность событий → признаки аномалии | Известный контрольный сценарий обнаруживается |
| Audit Service | Решения/действия → неизменяемая по контракту история | Идентификатор решения можно найти после перезапуска worker |
| Control Gateway | Разрешённое предложение → игровой запрос | Запрещённое событие не достигает устройства; права проверяются повторно |
| Health Monitor | Проверки компонентов → статус готовности | Падение одной реплики обнаруживается, ложная готовность не завершает финал |

Это собственные учебные сервисы HOSTFALL, не существующие универсальные продукты.
До финала игрок уже применяет процессы/службы, IP/HTTP, программы, события/очереди,
контейнеры, Pod/Deployment/Service, конфигурации, readiness, логи и восстановление.
Повторное появление процесса в первой комнате — ранняя модель вопроса о желаемом состоянии;
оно не объявляется Kubernetes и не использует вымышленные kubectl-команды.

## Настоящая лаборатория

Возможный инструмент — [kind](https://kind.sigs.k8s.io/docs/user/quick-start/) (источник
просмотрен 2026-11-06), но выбор версии/платформы и реальная проверка впереди. Unity
общается с отдельным ограниченным lab broker. В брокере не должно быть API «выполни любую
строку shell». Нужны явное согласие, собственный kubeconfig/context, проверка контекста
перед каждой операцией, именованная лаборатория и whitelist структурированных действий.
Не использовать production credentials, default kubeconfig или чужие namespace.

Недоверенный код отделён от привилегированного provisioning. Для kind container nodes
и произвольных учебных workload это разные уровни доверия; небезопасные права kind-узлов
нельзя переносить на workloads игрока. При необходимости размещать весь lab в отдельной
VM, а не обещать строгую изоляцию одним контейнером. Никаких host home mounts, Docker
socket в недоверенном workload, произвольных образов или privileged workload.
Учебные образы закрепляются digest, есть CPU/RAM quotas, сетевые ограничения, ограниченный
RBAC, безопасная отмена и очистка только ресурсов конкретной лаборатории.

## Acceptance до интеграции финала

1. Версии kind/kubectl/Kubernetes и образов закреплены; команды проверены в реальном контексте lab.
2. Обязательные Deployment существуют, сервисы имеют готовые endpoints и обмениваются событиями.
3. Разрешённое тестовое событие доходит до симуляции; запрещённое отклоняется и попадает в аудит.
4. Неверная конфигурация readiness ломает проверку, а не маскируется анимацией.
5. Остановка одной реплики не уничтожает политику/аудит, восстановление наблюдается.
6. Отмена не затрагивает сторонние кластеры, файлы и контейнеры; очистка повторяема.

Пока Docker/kind/kubectl не устанавливаются и кластеры не создаются. Команды в стартовой
статье имеют статус «пример для чтения», а не «выполнено».
